# ประเภทหนังสือของชุดงานจัดซื้อจัดจ้าง

ใช้ `DocumentType` และรายการทั้ง 13 แบบจาก `src/lib/templates.ts` ชุดเดียวกับหน้าร่างหนังสือหลัก รหัส D01–D14 บอกขั้นตอนงาน ส่วนชนิดหนังสือบอกว่าเอกสารนั้นเป็นหนังสือภายใน คำสั่ง ประกาศ หรือแบบอื่น

| ประเภทในระบบหลัก | เอกสารตั้งต้นในชุดงาน |
|---|---|
| หนังสือภายใน (บันทึกข้อความ) | D01, D02, D03, D05, D07, D12, D13, D14 |
| คำสั่ง | D06 คำสั่งแต่งตั้งผู้ตรวจรับ |
| ประกาศ | D08 ประกาศผู้ชนะ |
| หนังสืออื่น | D04 TOR, D09 ใบสั่งซื้อ/จ้าง, D10 ข้อมูล e-GP, D11 ใบตรวจรับ และไฟล์หลักฐาน |

อีก 9 ประเภทที่อยู่ในตัวเลือกเดียวกันคือ หนังสือภายนอก หนังสือประทับตรา ระเบียบ ข้อบังคับ แถลงการณ์ ข่าว หนังสือรับรอง รายงานการประชุม และบันทึก เจ้าของเรื่องแก้ประเภทของแต่ละรหัสได้ตามเอกสารจริง และกรองดูชุดเอกสารตามประเภทได้ ไม่ต้องสร้างเอกสารให้ครบทั้ง 13 ประเภทในทุกงาน

การจัดหมวดไม่ใช่การเปลี่ยนหน้าตาแม่แบบโดยอัตโนมัติ แม่แบบที่สร้าง Word ได้ในรอบนี้ยังเป็น D01 และ D07 ตามต้นฉบับที่ตรวจแล้ว ส่วนคำสั่ง ประกาศ และแบบอื่นแสดงสถานะรอเชื่อมแม่แบบหรือแนบไฟล์ตามจริง ไม่ใช้แบบบันทึกข้อความไปสร้างเป็นคำสั่งหรือประกาศ

ประเภทเก็บในข้อมูลของแต่ละงาน เมื่อสร้างหรือแนบไฟล์จะบันทึกประเภท ณ เวลานั้นใน metadata ของไฟล์ด้วย เพื่อรักษาประวัติฉบับเก่า งานและไฟล์รุ่นก่อนยังอ่านได้โดยใช้ประเภทเริ่มต้นจากรหัสเอกสาร

หน้าร่างใช้ `EditorLayout` ตัวเดียวกับหน้าหนังสือภายใน/ภายนอก รวมตัวลากแบ่งพื้นที่ การใช้คีย์บอร์ด และค่าความกว้างที่จำไว้ การจัดรูปแบบเอกสารยังคงใช้แม่แบบต้นฉบับของงานพัสดุ ไม่เปลี่ยนครุฑ ฟอนต์ หรือตำแหน่งลงนามตามขนาดของหน้าจอ

ติดตั้งรุ่นนี้ในระบบหลักแล้ว ตรวจผ่าน TypeScript, production build, ชุดทดสอบที่เกี่ยวข้อง 42 ข้อ และการทดสอบผ่าน Chrome รวมการวัดพิกัดแบบกรอก/preview การปรับตัวแบ่งด้วยคีย์บอร์ด การกรองประเภท และการบันทึกประเภท ตรวจข้อมูลเดิม 16 ตารางเทียบสำรองก่อนอัปเดตว่าคงเดิม งานเดิม 1 งานยังอยู่ครบ และการทดลอง preview ในระบบจริงไม่เพิ่มงานหรือไฟล์ส่งออก หลักฐานอยู่ที่ `output/procurement-main-install/verified-live.json`, `installed-live-editor.png` และ `installed-document-types.png`

ชุดเอกสารนี้จัดกลุ่มอยู่ในงานจัดซื้อจัดจ้าง ยังไม่ได้คัดลอกไฟล์ทั้งหมดไปเป็นรายการร่างอิสระในแดชบอร์ดหนังสือ เพราะต้องรักษาความเชื่อมโยงกับงาน แม่แบบ และเวอร์ชัน การเชื่อมทะเบียน/แดชบอร์ดกลางต่อไปต้องใช้การอ้างอิงรายการเดียว ไม่สร้างสำเนาหลายชุดที่แก้ข้อมูลแยกจากกัน
