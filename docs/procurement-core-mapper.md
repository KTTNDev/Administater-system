# เชื่อมจัดซื้อจัดจ้างกับระบบร่างหนังสือหลัก

ระบบเชื่อมเอกสารจัดซื้อจัดจ้าง 15 ฉบับเข้าสู่ Core Draft พร้อม Layout เฉพาะ TOR/ใบสั่งซื้อ/ใบตรวจรับ/ภาพประกอบ ใช้ตัวจัดหน้าเดียวกันใน Preview, PDF และตัววัดตำแหน่งสำหรับ Word ปิดระบบร่างเก่าและ Word COM แล้ว งานเก่ายังค้นและดาวน์โหลดต้นฉบับได้ในคลังอ่านอย่างเดียว

## การใช้งาน

1. เปิดงานในแบบฟอร์มจัดซื้อจัดจ้างชุดใหม่ กรอกข้อมูลกลาง เลขที่ และวันที่
2. กด **สร้าง/อัปเดตชุดร่างเอกสาร** ครั้งแรกสร้างครบ 15 ฉบับ ครั้งถัดไปยืนยันอัปเดตเนื้อหาจากข้อมูลกลาง
3. กดชื่อเอกสารใน **ลายแทงเรียงแฟ้ม** เพื่อเปิด Core Editor ตรงฉบับและใช้ลายเซ็น/Text Box/ภาพ/PDF ได้ทันที หากยังไม่เคยสร้างร่าง ระบบสร้างความสัมพันธ์ก่อนเปิดให้
4. ปุ่ม **ดูตัวอย่างในหน้านี้** อ่านร่าง Core ฉบับที่บันทึกไว้ตาม `draftId` เดียวกับหน้าร่าง ทั้งข้อความ Text Box ภาพ และ PDF แนบ การส่งออก PDF/Word/ZIP จากหน้าจัดซื้อใช้ร่าง Core เหล่านี้เช่นกัน ไม่มีการสร้างเอกสารทางเลือกจากข้อมูลกลางระหว่าง Preview หรือ Export
5. เมื่อเปลี่ยนข้อมูลกลาง ให้บันทึกร่างที่เปิดในหน้าต่างอื่นก่อน แล้วกด **สร้าง/อัปเดตชุดร่างเอกสาร** และยืนยันการอัปเดต

ระบบใช้ draftId เดิม การเปิดฉบับที่มีอยู่จะไม่ Sync หรือทับข้อความที่แก้ไว้ การกดปุ่มอัปเดตทั้งชุดจึงมีคำยืนยันแยก หากเอกสารอยู่ในถังขยะ ต้องกู้คืนเอกสารเดิมก่อน

เมื่อบันทึกใน Core อีกแท็บ หน้าจัดซื้อโหลดฉบับล่าสุดเมื่อกลับมาหรือได้รับเหตุการณ์บันทึก ใช้ปุ่ม **โหลดฉบับล่าสุด** ได้ด้วย แสดงเฉพาะสิ่งที่บันทึกแล้ว หากยังไม่มีร่างจะแจ้งให้สร้างชุดร่างก่อน ไม่มีการย้อนกลับไปใช้เอกสารจากเอนจินเดิม

## ผู้เสนอและแนวลงนาม

- บันทึกข้อความใส่ผู้เสนอ/เจ้าของเรื่องหลักของฉบับนั้นอัตโนมัติเพียงคนเดียว ไม่เติมผู้เสนอเพิ่มเติมหรือช่องความเห็นของผู้ลงนามอื่น เอกสารเฉพาะ เช่น ใบสั่งซื้อและภาพประกอบ ให้จัดผู้ลงนามด้วย Text Box
- ร่างที่ผูกไว้ก่อนหน้านี้ใช้กติกาเดียวกันในการแสดงผล โดยไม่ลบ Text Box ภาพลายเซ็น หรือไฟล์แนบเดิม การ Sync ไม่เพิ่มวัตถุลอยอัตโนมัติ
- หัวบันทึกข้อความวัดแนวเริ่มตัว **ข** ในคำว่า **ข้อความ** ด้วยฟอนต์ที่ฝังจริง ให้คำว่า **วันที่** และขอบเริ่มช่องผู้เสนออยู่แนวเดียวกัน ชื่อกับตำแหน่งจัดกึ่งกลางในช่อง และคงพื้นที่เซ็น 4 บรรทัดแม้ย้ายขึ้นหน้าถัดไป
- กล่องข้อความมีปุ่ม **จัดแนวกับวันที่ (ข)** ซึ่งย้ายเฉพาะกล่องที่ผู้ใช้กด ไม่ย้ายกล่องเดิมระหว่าง Sync

## เส้นทาง Preview และ Export

- `POST /api/procurement/preview-html`: `{caseId,docId,expectedVersions?}` อ่านร่างที่ผูกไว้แล้วส่ง HTML จาก `documentHtml()` ของ Core
- PDF/Word ใช้ `/api/procurement/export/pdf` และ `/docx` โดยส่ง `caseId`, `caseVersion?`, `expectedVersions?` และตัวเลือกชุดเอกสาร ไม่รับ `caseInput`/`agency` สำหรับสร้างเอกสารอีกชุด
- PDF รวมไฟล์แนบของ Core ต่อท้ายแต่ละฉบับและรักษาลำดับ/จำนวนชุด Word ส่งออกด้วย `renderWord()` ตัวเดียวกับหน้าร่าง ZIP มีข้อมูล `draftId`/version ของแต่ละฉบับ
- ตรวจร่างหาย อยู่ในถังขยะ หรือ version เปลี่ยนก่อนเริ่มสร้างไฟล์ โดยไม่ Sync แก้ข้อความให้เอง ปกและแผ่นคั่นแสดงเฉพาะข้อมูลจัดแฟ้มและไม่เติมช่องเซ็น

## การถอดระบบ Word เบื้องหลัง

- ย้ายใบต่อไป `src/lib/word-continuation.ts` และเปลี่ยน Core Word exporter ให้ใช้โมดูลกลาง เก็บชื่อโมดูลเก่าเป็น re-export สำหรับอ่านแพ็กเกจเก่า
- การตรวจเลขและจองเลข Core อ่านเลขจากเคส/ทะเบียนชุดใหม่ พร้อมป้องกันการอ้าง provenance ปลอมเพื่อใช้เลขที่จองไว้ เฉพาะร่างที่ผูกกับช่องเอกสารจริงเท่านั้นใช้เลขเจ้าของงานได้
- เลขใบสั่งซื้อที่ใช้ปีงบประมาณเดียวกันห้ามซ้ำ แม้วันที่เอกสารอยู่คนละปีปฏิทิน ส่วนเลขหนังสืออื่นคงตรวจตามปีปฏิทินของทะเบียน
- ปฏิทินรวมวันครบสัญญาชุดใหม่ ลิงก์ `coreCase` เปิดงานใหม่ตรงแท็บเลขที่/วันที่ ส่วนรายการเก่าเปิด `archiveCase` แบบอ่านอย่างเดียว บุ๊กมาร์ก `case` เดิมยังอ่านได้
- เก็บ Schema เก่าทั้งกรณีงาน แม่แบบ ไฟล์ และประวัติ สำหรับตรวจ/กู้คืน backup และอ่านคลัง ไม่แก้ข้อมูลหรือแปลงรูปแบบงานเดิมโดยอัตโนมัติ
- API เก่าที่ใช้สร้าง/แก้/Preview ตอบ 410 หลังตรวจสิทธิ์ เส้นทางใหม่ `workspace`, `core-drafts`, `contracts`, `archive`, `export` และ `photos` ยังทำงานตามหน้าที่
- ลบสคริปต์ Word COM และตัวเรียกออกจากระบบ/แพ็กเกจ Desktop หน้า Lab เดิมเปลี่ยนทางมาหน้าจัดซื้อใหม่ ไม่มีปุ่มเปิดระบบร่างเดิม
- เปิดงานเก่าจาก **เอกสารที่จัดเก็บก่อนย้ายระบบ** เพื่ออ่านข้อมูล เลขที่ วันที่ และดาวน์โหลดไฟล์ต้นฉบับ โดยไม่เรียกตัวจัดหน้าใด ๆ

## กฎข้อมูล

- `core/mapper.ts`: `mapProcurementCaseToDrafts(input, agency)` เป็นฟังก์ชันไม่มี I/O ใช้สูตรราคา/VAT/บาทตัวอักษรและข้อความจาก Phase 1–2 คืน `{docId,copies,draft}` ครบ 15 ฉบับ รวมตัวเลือกร่างเองของช่อง e-GP
- แปดบันทึกใช้ `internal`; คำสั่งใช้ `order`; ประกาศใช้ `announcement`; หนังสือแจ้งใช้ `external`; อีกสี่ฉบับใช้ `other` คู่กับ `procurement-tor`, `procurement-po`, `procurement-inspection`, `procurement-photos`
- วันที่ไม่ทราบคงว่าง ไม่เดาวันปัจจุบัน ประกาศไม่มีเลขพิมพ์จากทะเบียนประกาศ หนังสือแจ้งใช้เลขของตัวเอง
- `syncProcurementDraft(current, generated)` อัปเดตฟิลด์ใน `SYNC_CONTENT_FIELDS`: หัวหนังสือ เนื้อหา ตารางราคา และข้อความผู้ลงนาม พร้อมหัวภาพรวม (`appendixTitle`) เฉพาะฉบับ 11.3 โดยไม่แก้ `floatingItems`, `appendixImages`, `attachmentFiles` รวมถึงภาคผนวกข้อความและการตั้งค่าจัดหน้าที่ผู้ใช้แก้เอง
- เนื้อหาที่แก้เฉพาะฉบับในฟิลด์เหล่านั้นจะถูกแทนที่เมื่อ Sync และสถานะกลับเป็นฉบับร่างเมื่อข้อความเปลี่ยน ตัวฟังก์ชันไม่เปลี่ยนวัตถุต้นทาง
- ภาพประกอบจากข้อมูลกลางถูกนำเข้าคลังภาพ Core เฉพาะครั้งแรก (ไม่เกิน 20 ภาพ/50 MB) Sync ภายหลังไม่เพิ่ม ลบ หรือเปลี่ยนภาพ แม้ภาพในงานจัดซื้อเปลี่ยน ผู้ใช้จัดการภาพต่อใน Core Editor
- เฉพาะฉบับ 11.3 หัวภาพรวม (`appendixTitle`) อัปเดตจากข้อมูลกลางได้ ส่วนคำบรรยายใน `appendixImages` คงเดิมตามที่ผู้ใช้จัดไว้ หัวภาคผนวกที่ผู้ใช้เพิ่มในฉบับอื่นจะคงเดิม
- ตำแหน่งลายเซ็นและ Text Box จะคงเดิมหลัง Sync จึงควรตรวจหน้าตัวอย่างก่อนพิมพ์ โดยเฉพาะเมื่อเนื้อหายาวขึ้น
- `procurementSource` ในร่างระบุเคสและช่องเอกสารต้นทาง ใช้เปิดเครื่องมือแนบ PDF/ภาคผนวกใน Core Editor ให้เอกสารจัดซื้อทุกประเภท ความสัมพันธ์ในตารางยังเป็นหลักสำหรับ Sync และฟังก์ชันจะปฏิเสธการ Sync ข้ามงานหรือข้ามช่องเอกสาร

## การบันทึกและ API

`procurement_core_drafts` ผูก `(case_id, doc_id)` แบบไม่ซ้ำ และ `draft_id` แบบไม่ซ้ำ เก็บจำนวนชุด เวอร์ชันข้อมูลกลางที่ใช้ และเวลา Sync เอกสารจริงอยู่ใน `documents` และมีประวัติ Core ปกติ

- `GET /api/procurement/core-drafts?caseId=...`: รายการผูกกับร่างล่าสุด (`draft:null` หากอยู่ในถังขยะ)
- `POST /api/procurement/core-drafts`: `{caseId,caseVersion,mode:'create'|'sync',expectedVersions?:{[docId]:version}}`
- Sync ต้องส่งเวอร์ชันปัจจุบันของร่างครบทุกฉบับ หากข้อมูลกลางหรือ Core เปลี่ยนไปจะตอบ conflict ให้โหลดรายการใหม่
- บันทึกทั้งชุดพร้อมความสัมพันธ์และภาพครั้งแรกในธุรกรรมเดียว เลขซ้ำหรือเวอร์ชันชนจะยกเลิกทั้งชุด ไม่ทิ้งเอกสารครึ่งชุด การทำสำเนาไฟล์ในเครื่องเกิดหลัง commit เท่านั้น
- API ตรวจผู้ใช้งานและ same-origin; ไม่อ่านพาธภาพหรือเรียก URL ที่ส่งจากผู้ใช้
- Backup/restore รวมตารางผูกนี้ และตรวจว่าร่างกับงานต้นทางอยู่ในชุดสำรองเดียวกัน สำรองเก่าที่ไม่มีตารางนี้ยังอ่านได้
- ลบงานจัดซื้อจะปลดความสัมพันธ์ แต่เก็บร่าง Core ไว้ ผู้ใช้ลบ/กู้คืนร่างผ่านระบบเอกสารได้เอง

## Layout เฉพาะและการคำนวณ

| เอกสาร | Layout | ส่วนแสดงผล |
| --- | --- | --- |
| 4.1 | `procurement-tor` | ชื่อเรื่อง/วิธีจัดซื้อ หัวข้อ TOR 9 ข้อ ตารางไม่มีเส้น ผู้ใช้วางผู้ลงนามด้วย Text Box |
| 10 | `procurement-po` | ครุฑ 3 ซม. ข้อมูลคู่สัญญา/หน่วยงาน 2 คอลัมน์ ตาราง 6 คอลัมน์และยอดรวมแบบรวมช่อง เงื่อนไข 6 ข้อ หมายเหตุ ผู้ใช้วางลายเซ็นคู่ด้วย Text Box |
| 11.2 | `procurement-inspection` | วันที่ ผลตรวจรับ/ค่าปรับแบบช่องเลือก ผู้ใช้วางผู้ตรวจรับหรือกรรมการด้วย Text Box |
| 11.3 | `procurement-photos` | ภาพจาก Core `appendixImages` ต่อเนื่องหลายหน้า ไม่มีหน้าปกว่าง และรับรองเฉพาะหน้าภาพสุดท้าย |

- `procurementForm` เก็บข้อความใต้หัวแบบฟอร์มและข้อมูลสองคอลัมน์ แก้ไขได้ในส่วนเนื้อหาของ Core Editor ข้อมูลวันที่ใต้ลายเซ็นเก่าเก็บไว้เพื่ออ่านสำรอง แต่ไม่เติมบล็อกผู้ลงนามอื่นให้อัตโนมัติ ส่วนหัวภาพใช้เครื่องมือเอกสารแนบท้ายเดิม
- Sync อัปเดต `procurementForm` และยกระดับร่างที่เคยเป็น `standard` ไปสู่ Layout เฉพาะ โดยยังรักษาองค์ประกอบวางอิสระ ภาพ และไฟล์แนบ
- ราคาต่อหน่วยในข้อมูลกลางเป็นราคาที่รวม VAT แล้ว หากร้านจด VAT ระบบถอดฐานภาษีด้วย `ยอดรวม × 100 / 107` ปัดเศษเป็นสตางค์ แล้วหาภาษีจากส่วนต่าง เช่น 1,520 บาท = ฐาน 1,420.56 + VAT 99.44 บาท ไม่บวก VAT ซ้ำ หากร้านไม่จด VAT จะไม่แสดงบรรทัด VAT
- ตัวสร้างทั้ง 15 ฉบับใช้สูตร/เนื้อหาชุดเดียวกับระบบจัดซื้อเดิม และแปลงตัวเลขในเนื้อหา/ข้อความแบบฟอร์มเป็นเลขไทย รวมตัวเลขในชื่อรุ่นสินค้า ส่วน ID วันที่ ISO และข้อมูลคำนวณยังเก็บเป็นชนิดข้อมูลเดิม
- เมื่อแก้ข้อความเฉพาะฉบับใน Core ระบบรักษาการแก้ไขนั้นจนกว่าจะกด Sync ใหม่ การคำนวณราคาอัตโนมัติทำจากรายการสินค้าในข้อมูลกลาง ไม่ตีความราคาที่พิมพ์แก้ในข้อความอิสระ
- ตารางยาวซ้ำหัวตาราง มีเลขหน้าไทย คำต่อมุมล่างขวา และหมายเหตุใบต่อ Word รักษาช่องรวมของตาราง ข้อมูลคู่คอลัมน์ และตำแหน่งลายเซ็นจากการวัด Preview ข้อความและตารางยังแก้ไขได้
- TOR ยึดขอบบน 2.5 ซม. ตามสเปก Phase 2 และคำยืนยันผู้ใช้ แม้ต้นแบบเก่าบางฉบับตั้งไว้ประมาณ 0.5 ซม. จำนวนหน้าจึงอาจต่างจากไฟล์เก่า
- ตารางใบสั่งซื้อรวมช่องจำนวนเงินตัวอักษรแนวตั้งด้านซ้าย และวางฐานภาษี/VAT/ยอดรวมด้านขวา ชุดยอดรวมจะย้ายหน้าพร้อมกัน ไม่แบ่งช่องรวมกลางชุด

## แนวหัวข้อบันทึกข้อความ

หัวข้อในบันทึกข้อความ เช่น เรื่องเดิม ข้อเท็จจริง ข้อกฎหมาย และข้อพิจารณา เริ่มที่แนวย่อหน้าบรรทัดแรกของเนื้อหา 2.5 ซม. ใช้ทั้งหัวข้อในช่องเนื้อหาอิสระ (`## หัวข้อ`) และการกรอกเนื้อหาแยกส่วนใน Core เดียวกัน โดย Preview/PDF/Word ใช้ตำแหน่งจากตัวจัดหน้าเดียวกัน ไม่ต้อง Sync เพื่อเปลี่ยนรูปแบบของร่างที่บันทึกไว้แล้ว
