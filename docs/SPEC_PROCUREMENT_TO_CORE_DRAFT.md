# SPEC: เชื่อมระบบจัดซื้อจัดจ้างเข้าสู่ Core Draft Engine (ยกเลิก Word COM)

> ข้อกำหนดล่าสุดจากผู้ใช้: Preview/PDF/Word/ZIP ในหน้าจัดซื้อต้องอ่านร่าง Core ที่บันทึกจริง ใส่อัตโนมัติเฉพาะผู้เสนอของบันทึกข้อความ 1 จุด ผู้ลงนามอื่นจัดด้วย Text Box โดยไม่เติมซ้ำ แนว “วันที่” และช่องผู้เสนออ้างอิงตัว “ข” ในหัว “บันทึกข้อความ” รายละเอียดโครงสร้างฟอร์มด้านล่างไม่ใช่คำสั่งให้เติมชื่อผู้ลงนามทุกคนอัตโนมัติ

> สถานะ 23 พฤศจิกายน 2569: เชื่อมปุ่มสร้าง/อัปเดตชุดร่างและรายการเรียงแฟ้มเข้าหน้า Core Editor แล้ว จัดการจุดเชื่อมโยงข้อ 4 ครบ และถอดตัวเรียก Word COM/ปุ่มเปิดระบบร่างเก่าแล้ว ข้อมูลเก่าและไฟล์ต้นฉบับอยู่ในคลังอ่านอย่างเดียว ดูรายละเอียดการใช้งานใน `docs/procurement-core-mapper.md`

## 1. สถาปัตยกรรมเป้าหมาย (Target Architecture)
- **Single-Entry Data:** ใช้ฟอร์มกรอกข้อมูลกลาง + ตัวคำนวณ VAT 7% / แปลงบาทเป็นตัวอักษรไทย / แปลงเลขไทย จาก `src/lib/procurement/` (`schema.ts`, `calculations.ts`, `formatting.ts`)
- **Document Engine (Core Draft):** เอกสารจัดซื้อจัดจ้างทั้ง 15 ฉบับ ต้องถูกสร้างและบันทึกเป็น `SavedDraft` ในตาราง `documents` ของระบบร่างหนังสือราชการหลัก (`src/lib/document.ts` + `src/lib/render-document.ts`) เพื่อให้ใช้งานฟีเจอร์ทั้งหมดของ Core Editor ได้ 100% ได้แก่:
  - ลาก/ย่อขยายลายเซ็น (`signature-editor` / `floatingItems`)
  - วางกล่องข้อความ (Text Box) / รูปภาพอิสระ (`floating-items-editor`)
  - จัดการรูปภาพภาคผนวก (`appendix-editor` / `appendixImages`)
  - แนบไฟล์ PDF ต่อท้าย (`attachment-editor` / `attachmentFiles`)
  - Live A4 Preview + Export PDF (`playwright` + `pdf-lib`) + Export DOCX Pure JS (`docx`)
- **Deprecate:** ยกเลิกระบบสั่งรัน MS Word เบื้องหลัง (`scripts/render-procurement-template.ps1` และ `LegacyProcurementWorkspace`) ทั้งหมด

## 2. การจับคู่เอกสารทั้ง 15 ฉบับเข้ากับ Core Draft Engine
1. **ใช้แบบหนังสือมาตรฐานเดิมใน `src/lib/templates.ts` (11 ฉบับ):**
   - `internal` (บันทึกข้อความ): ไฟล์ `1` (ขออนุมัติหลักการ), `2` (มอบหมาย TOR), `3` (รายงานผล TOR), `6.1` (รายงานขอซื้อ), `7` (รายงานผลพิจารณา/ขออนุมัติสั่งซื้อ), `11.1` (รายงานผลตรวจรับ), `12` (รายงานผลส่งตั้งหนี้), `13` (ขออนุมัติเบิกจ่ายเงิน)
   - `order` (คำสั่ง): ไฟล์ `6.2` (คำสั่งแต่งตั้งผู้ตรวจรับ - 3 ชุด)
   - `announcement` (ประกาศ): ไฟล์ `8` (ประกาศผู้ชนะการเสนอราคา - 3 ชุด)
   - `external` (หนังสือภายนอก): ไฟล์ `9` (หนังสือแจ้งลงนามในสัญญา - 3 ชุด)
2. **เพิ่ม Layout เฉพาะใน `src/lib/render-document.ts` ให้ตรงฟอร์มราชการเป๊ะ (4 ฉบับ):**
   - `procurement-tor` -> ไฟล์ `4.1 TOR` (รายละเอียดคุณลักษณะเฉพาะ 9 ข้อ + ใบต่อ)
   - `procurement-po` -> ไฟล์ `10. ใบสั่งซื้อ` (หัวกระดาษตราครุฑ, ข้อมูลผู้ขาย/ส่วนราชการ 2 คอลัมน์, ตารางรายการ + ถอด VAT 7%, เงื่อนไข 6 ข้อ, ลายเซ็นผู้สั่งซื้อ/ผู้รับใบสั่งซื้อคู่กัน - 2 ชุด)
   - `procurement-inspection` -> ไฟล์ `11.2 ใบตรวจรับการจัดซื้อ/จัดจ้าง` (หัวข้อ, ช่องติ๊กถูก ☑/☐ ผลการตรวจรับและค่าปรับ, ลายเซ็นผู้ตรวจรับ - 2 ชุด)
   - `procurement-photos` -> ไฟล์ `11.3 รูปภาพประกอบ` (ดึงภาพจาก `appendixImages` ของ Core Draft จัดวางพร้อมข้อความรับรองและชื่อผู้ตรวจรับ)

## 3. กฎการซิงก์ข้อมูลและรักษาลายเซ็น (Non-Destructive Sync)
- เก็บความสัมพันธ์ระหว่าง `caseId` (เคสจัดซื้อจัดจ้าง) กับ `draftId` ของเอกสารทั้ง 15 ฉบับ
- เมื่อผู้ใช้แก้ไขข้อมูลกลาง (เช่น เปลี่ยนวันที่ เลขที่หนังสือ หรือราคา) แล้วกด **"อัปเดตเอกสารจากข้อมูลกลาง"**:
  - **อัปเดตเฉพาะ:** ข้อมูลหัวหนังสือ, เนื้อหา (`body` / `contentBlocks`), ตารางราคา, และข้อความลงนาม
  - **ห้ามลบ/ห้ามทับ:** `floatingItems` (ลายเซ็นและ Text Box ที่ผู้ใช้ลากวางไว้), `appendixImages`, และ `attachmentFiles` (ผู้ใช้ยังคงแก้ไขหรือลบลายเซ็นเองได้ตามปกติในหน้า Core Editor)

## 4. รายการจุดเชื่อมโยงที่ต้องจัดการก่อนลบ Word COM เบื้องหลัง
1. ย้ายฟังก์ชัน `continuationFooter()` ออกจาก `src/lib/procurement-pagination.ts` ไปไว้ใน `src/lib/word-continuation.ts` เพื่อไม่ให้ `src/lib/word.ts` พัง
2. อัปเดต `checkNumber()` และ `reserveDraftNumber()` ใน `src/lib/db.ts` ให้ตรวจเลขซ้ำจากระบบใหม่
3. อัปเดตลิงก์ใน `src/components/work-calendar.tsx` ไม่ให้เด้งไปเปิด `LegacyProcurementWorkspace`
4. คงการอ่าน Schema เก่าแบบ read-only ใน `src/lib/workspace-restore.ts` เพื่อไม่ให้การกู้คืนไฟล์ Backup เก่าล้มเหลว
