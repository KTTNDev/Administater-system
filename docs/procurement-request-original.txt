คุณคือ Senior Full-Stack Developer ที่เชี่ยวชาญการพัฒนาระบบงานราชการส่วนท้องถิ่น (อปท./เทศบาล) ของไทย และเข้าใจระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560 รวมถึงการทำงานเชื่อมโยงทางเอกสารกับระบบ e-GP และ e-LAAS เป็นอย่างดี

ฉันต้องการพัฒนาโมดูลใหม่ชื่อว่า "ระบบอำนวยความสะดวกงานจัดซื้อจัดจ้างและติดตามการวางฎีกา (Municipal Procurement & Bill Tracking Helper)" เพิ่มเติมเข้าไปในโปรเจกต์ปัจจุบันของฉัน

### ข้อกำหนดด้านเทคนิคและฐานข้อมูล (สำคัญมาก - ห้ามเขียนมั่ว):
1. **ใช้ฐานข้อมูล SQLite และโครงสร้างเดิมที่มีอยู่ในโปรเจกต์:** ให้ตรวจสอบไฟล์เชื่อมต่อฐานข้อมูล (Database Connection / Query Helper) และรูปแบบการเขียนโค้ด (Tech Stack, UI Components, โครงสร้างโฟลเดอร์) ที่ใช้อยู่เดิมในโปรเจกต์นี้ก่อน แล้วเขียนโค้ดใหม่ให้สอดคล้องกับระบบเดิม 100% ห้ามเปลี่ยนไปใช้ ORM ตัวอื่นที่ไม่ได้ติดตั้งไว้ในโปรเจกต์เด็ดขาด
2. **เป้าหมายของโมดูล:** ไม่ได้ทำมาแทนที่ e-GP หรือ e-LAAS แต่ทำมาเพื่อจัดการ "งานเตรียมเอกสารนอกระบบ การตามบิลร้านค้า และการเช็กความครบถ้วนของเอกสารก่อนส่งกองคลังวางฎีกา" เพื่อลดความผิดพลาดและป้องกันเอกสารโดนกองคลังตีกลับ

กรุณาออกแบบตาราง SQLite, Logic และหน้า UI ให้ครบถ้วนตามความต้องการดังต่อไปนี้:

### 1. โครงสร้างตารางฐานข้อมูล (SQLite Tables)
สร้างคำสั่ง SQL (`CREATE TABLE IF NOT EXISTS`) และ TypeScript Interfaces ที่รองรับข้อมูลต่อไปนี้:
- **procurement_cases (แฟ้มงานจัดซื้อจัดจ้าง):**
  - `id`, `title` (ชื่องาน/โครงการ), `fiscal_year` (ปีงบประมาณ), `budget_source` (แหล่งเงินงบประมาณ/แผนงาน)
  - `procurement_type` (ประเภทงาน: `'MATERIAL_PURCHASE'` [ซื้อวัสดุ], `'HIRE_OF_WORK'` [จ้างทำของ/ซ่อมแซม], `'SERVICE_CONTRACT'` [จ้างเหมาบริการ], `'URGENT_UNDER_10K'` [วงเงินไม่เกิน 10,000 บาท ข้อ 79 วรรคสอง])
  - `total_amount` (ยอดรวม), `vat_amount` (ภาษีมูลค่าเพิ่ม 7%), `withholding_tax` (หัก ณ ที่จ่าย 1%), `net_payable` (ยอดจ่ายจริงสุทธิ)
  - `egp_project_number` (เลขที่โครงการ e-GP - Optional), `egp_contract_number` (เลขคุมสัญญา/ใบสั่งซื้อ e-GP - Optional), `elaas_dika_number` (เลขที่ฎีกาจากระบบ e-LAAS - Optional)
  - `status` (`'DRAFT'`, `'WAITING_QUOTATION'`, `'ORDERED_WAITING_BILL'`, `'BILL_RECEIVED'`, `'INSPECTED'`, `'SENT_TO_FINANCE'`, `'PAID'`, `'REJECTED_BY_FINANCE'`)
  - ลำดับวันที่สำคัญ (เก็บเป็น ISO Date String `YYYY-MM-DD`): `approval_request_date` (วันขออนุมัติหลักการ), `quotation_date` (วันในใบเสนอราคา), `order_date` (วันสั่งซื้อ/สั่งจ้าง), `delivery_and_bill_date` (วันส่งมอบ/วันที่ในบิล), `inspection_date` (วันตรวจรับพัสดุ)
  - `vendor_id` (เชื่อมกับตารางร้านค้า), `created_at`, `updated_at`
- **vendors (ฐานข้อมูลร้านค้า/ผู้รับจ้างประจำ):**
  - `id`, `name`, `tax_id` (เลขผู้เสียภาษี 13 หลัก), `address`, `phone`, `bank_account_no`, `bank_name`, `is_vat_registered` (0 หรือ 1)
- **bill_attachments (ระบบเก็บและตามบิล):**
  - `id`, `case_id`, `bill_type` (ใบเสนอราคา, ใบส่งของ/ใบกำกับภาษี, ใบเสร็จรับเงิน/บิลเงินสด, ภาพถ่ายพัสดุ/หน้างาน), `bill_number`, `issue_date`, `amount`, `file_path`, `is_verified` (ตรวจความถูกต้องของหัวบิล/ลายเซ็นแล้วหรือยัง 0 หรือ 1), `notes`
- **checklist_items (รายการสิ่งที่ต้องทำและเอกสารประกอบตามระเบียบ):**
  - `id`, `case_id`, `step_order`, `title` (ชื่อขั้นตอน/ชื่อเอกสาร), `category` (`'PRE_EGP'`, `'IN_EGP'`, `'INSPECTION'`, `'FINANCE_DIKA'`), `is_completed` (0 หรือ 1), `completed_at`, `is_required` (0 หรือ 1)

### 2. Business Logic & Auto-Checklist Generator
สร้างฟังก์ชันอัตโนมัติ เมื่อมีการ Insert ข้อมูล `procurement_cases` ใหม่ ให้ระบบสร้างรายการใน `checklist_items` อัตโนมัติตามประเภทงานและวงเงิน (ใช้ SQLite Transaction) ดังนี้:
- **กรณีทั่วไป (วิธีเฉพาะเจาะจง ไม่เกิน 500,000 บาท):**
  1. บันทึกขออนุมัติหลักการ/รายงานขอซื้อขอจ้าง (ระเบียบฯ ข้อ 22)
  2. ขอใบเสนอราคาจากร้านค้า (ตรวจชื่อหัวบิลให้ตรงกับเทศบาล และไม่มีรอยขูดลบ)
  3. บันทึกรายงานผลการพิจารณาและขออนุมัติสั่งซื้อ/สั่งจ้าง
  4. ลงข้อมูลในระบบ e-GP และนำเลขโครงการ/เลขคุมสัญญามากรอกในระบบ
  5. ออกใบสั่งซื้อ/ใบสั่งจ้าง (PO) แจ้งร้านค้า
  6. รับมอบพัสดุ + เก็บบิลตัวจริง (ใบส่งของ/ใบกำกับภาษี) + ถ่ายภาพพัสดุ/ผลงานประกอบการเบิก
  7. จัดทำใบตรวจรับพัสดุ (ผู้ตรวจรับลงนามครบถ้วน)
  8. ทำบันทึกขออนุมัติเบิกจ่ายเงิน รวบรวมเอกสารส่งกองคลังเพื่อตั้งหนี้และวางฎีกาใน e-LAAS
- **เงื่อนไขพิเศษที่ต้องเพิ่มอัตโนมัติ:**
  - ถ้าเป็นงานซ่อมแซม (`HIRE_OF_WORK`) ให้แทรก Checklist ขั้นตอนแรกสุด: *"บันทึกแจ้งซ่อม + ตรวจสอบประวัติการซ่อมครุภัณฑ์เดิม + ภาพถ่ายก่อนซ่อม/หลังซ่อม"*
  - ถ้าวงเงินไม่เกิน 10,000 บาท กรณีจำเป็นเร่งด่วน (`URGENT_UNDER_10K`) ให้ลดรูป Checklist เหลือ: *"1. เก็บใบเสร็จรับเงิน/บิลเงินสด (ถ้าบิลเงินสดต้องมีสำเนาบัตรประชาชนผู้รับเงิน) 2. ถ่ายภาพพัสดุ 3. ทำบันทึกรายงานขอความเห็นชอบตามข้อ 79 วรรคสอง 4. ส่งเบิกกองคลังเพื่อวางฎีกา"*

### 3. ระบบตรวจสอบความถูกต้อง (Validation Rules)
- **Date Timeline Validator:** สร้างฟังก์ชันตรวจสอบลำดับวันที่ในฟอร์ม ห้ามให้วันที่ขั้นตอนหลังเกิดก่อนขั้นตอนหน้าเด็ดขาด (`approval_request_date` <= `quotation_date` <= `order_date` <= `delivery_and_bill_date` <= `inspection_date`) หากกรอกผิดลำดับให้แจ้งเตือนสีแดงพร้อมบอกเหตุผลตามระเบียบพัสดุทันที
- **Bill Verification Check:** ในส่วนของการรับบิล มี Checkbox เตือนจุดตายก่อนกดยืนยันรับบิล: (1) ชื่อ-ที่อยู่เทศบาลถูกต้อง (2) วันที่ในบิลไม่เกิดก่อนวันสั่งซื้อ (3) มีลายเซ็นผู้รับเงิน/ผู้ส่งของครบถ้วน
- **Pre-LAAS Gatekeeper:** ห้ามเปลี่ยนสถานะงานเป็น `SENT_TO_FINANCE` (ส่งกองคลังวางฎีกา) จนกว่า `checklist_items` ที่ `is_required = 1` จะถูกติ๊กครบทุกข้อ

### 4. หน้าจอการใช้งาน (UI Components)
สร้างหน้าจัดการงานจัดซื้อจัดจ้างให้เข้ากับธีมของระบบเดิม โดยมีองค์ประกอบดังนี้:
1. **Summary Dashboard:** แสดงการ์ดสรุปจำนวนงานที่ "กำลังตามบิลร้านค้า", "รอตรวจรับ/รอเซ็น", "พร้อมส่งคลังวางฎีกา" และยอดเงินรวม
2. **Case Detail & Checklist View:** หน้าแสดงรายละเอียดแต่ละงาน มี Progress Bar, รายการ Checklist ให้กดติ๊กเมื่อทำเสร็จ, ช่องบันทึกเลข e-GP และเลขฎีกา e-LAAS เพื่อใช้อ้างอิงค้นหาย้อนหลัง
3. **Tax & Net Payable Calculator:** เครื่องคิดเลขคำนวณยอดเงินในฟอร์มอัตโนมัติ (กรอกยอดรวม -> เลือกมี VAT 7% หรือไม่ -> เลือกหัก ณ ที่จ่าย 1% สำหรับงานจ้างหรือไม่ -> คำนวณยอดเงินสุทธิที่ต้องตั้งเบิกในฎีกา)

**สิ่งที่ต้องทำเป็นลำดับแรก:**
ตรวจสอบโครงสร้างโปรเจกต์และการตั้งค่า SQLite เดิมของฉันก่อน จากนั้นสรุปแผนการสร้างไฟล์ (Migration/Table Init, API/Actions, และ UI) แล้วลงมือเขียนโค้ดให้ครบถ้วน
