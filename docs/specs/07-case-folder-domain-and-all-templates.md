# Phase 7: General Sarabun Case Folder Domain, Cross-Module Linking & All 7 Official Document Types

> **Target Repository:** `sarabun-workspace` (Next.js 16.4, TypeScript 5.9, Zod 4.6, Vitest 5)
> **Prerequisite:** Phases 1–6 (`src/lib/procurement/` and `src/lib/inventory/`) are implemented and passing tests.
> **Core-First Architecture Rule (Mandatory):** All official document forms generated by Case Folders MUST use the workspace **Core document engine** (`src/lib/document.ts`, `src/lib/render-document.ts`, `src/lib/pdf.ts`, `src/lib/word.ts`) via `src/lib/cases/core/` mapper & bindings (`case_core_drafts`) as the single source of truth for A4 previews, PDF binders, Word exports, and Quick Blank Local Word forms, with 1-click deep-linking into the Core Editor (`DocumentForm`) and back.
> **Objective:** Build a flexible **"แฟ้มงานสารบรรณ" (Case / Project Folder)** domain and template engine that supports ANY municipal administrative job:
> 1. **Project Folder (`CaseFolder`)** with shared case-level variables (`{{var.xxx}}`) that propagate to all documents inside the folder.
> 2. **All 7 Official Thai Government Document Types** + **External File Slot** + **Live Cross-Module Links** (pulling existing Procurement cases or Inventory requisitions directly into the folder's roadmap without duplicating data).
> 3. **Dynamic Roadmap ("ลายแทง") & Live Cross-Reference (`@ref`)** — when Doc 2 references Doc 1, changing Doc 1's running number or date updates Doc 2's citation text automatically.
> 4. **Blueprints & Safe Clone** — save any finished folder as a reusable template or clone it safely with all old numbers, dates, and external files wiped clean.

## 2. All 9 Supported Item Types Inside a Case Folder (`schema.ts`)

Every `CaseFolder` holds an ordered list of `CaseItem` entries grouped into user-defined submission stages (`รอบเสนอแฟ้ม`, e.g. `รอบที่ 1 ขออนุมัติหลักการ`, `รอบที่ 2 ดำเนินการ`, `รอบที่ 3 รายงานผล/เบิกจ่าย`):

### A. 7 Native Generated Official Document Types (`kind: "GENERATED_DOC"`)
1. **`INTERNAL_MEMO` (บันทึกข้อความ):**
   - Garuda `1.5 cm` top-left, Track 1 (`ภก 52906/xxxx`).
   - Structured sections (optional toggles): `เรื่องเดิม`, `ข้อเท็จจริง`, `ข้อระเบียบและกฎหมาย`, `ข้อพิจารณาและข้อเสนอ`.
   - Configurable approval chain: `NONE` | `2_TIER` (ผอ.กอง เสนอ -> ปลัด -> นายก) | `3_TIER` (จนท. เสนอ -> ผอ.กอง -> ปลัด -> นายก) | `4_TIER_VERTICAL` (ความเห็นเรียงแนวตั้งแบบหนังสือส่งตั้งหนี้).
2. **`EXTERNAL_LETTER` (หนังสือภายนอก):**
   - Garuda `3.0 cm` centered, Track 4 (`ภก 52806/xxxx`), agency address top-right, date, `เรื่อง`, `เรียน`, optional `อ้างถึง` (live `@ref` list), optional `สิ่งที่ส่งมาด้วย`, body paragraphs, `ขอแสดงความนับถือ`, Mayor signature, bottom-left division/phone/fax footer.
3. **`MUNICIPAL_ORDER` (คำสั่งเทศบาล):**
   - Garuda `3.0 cm` centered, Track 2 (`xxxx/25xx`), `คำสั่งเทศบาลตำบลฉลอง`, `เรื่อง`, centered dotted divider, body + numbered appointees/committee list, `สั่ง ณ วันที่`, Mayor signature, optional Routing Initials Strip (`FIRST_COPY_ONLY` / `ALL_COPIES` / `NONE`).
4. **`ANNOUNCEMENT` (ประกาศเทศบาล):**
   - Garuda `3.0 cm` centered, Track 3 (`registryLogNo` logged in book only, NOT printed on page), `ประกาศเทศบาลตำบลฉลอง`, `เรื่อง`, centered dotted divider, body, `ประกาศ ณ วันที่`, Mayor signature, optional Routing Initials Strip.
5. **`CERTIFICATE_OR_INVITATION` (หนังสือรับรอง / หนังสือเชิญวิทยากร / หนังสือเชิญประชุม):**
   - Garuda `3.0 cm` centered; sub-variant selector:
     - `INVITATION`: formal external letter structure pre-populated with event date, time, location, and agenda table (pulled from Case Shared Variables).
     - `CERTIFICATE`: centered `หนังสือรับรอง`, `เลขที่`, official certification body, `ให้ไว้ ณ วันที่`, Mayor/Director signature.
6. **`PROJECT_PROPOSAL_OR_ATTACHMENT` (เอกสารประกอบ / ร่างโครงการ / รายงานการประชุม / ตารางแนบท้าย):**
   - No Garuda, flexible sections (`ชื่อโครงการ`, `หลักการและเหตุผล`, `วัตถุประสงค์`, `เป้าหมาย`, `ระยะเวลา/สถานที่`, `งบประมาณ` with optional itemized table, `ผู้รับผิดชอบโครงการ` -> `ผู้เห็นชอบ` -> `ผู้อนุมัติ`), full multi-page continuation support (`- ๒ -` header + repeated `<thead>` / `<w:tblHeader/>`).
7. **`PHOTO_SHEET` (หน้ารูปภาพประกอบกิจกรรม/หลักฐาน):**
   - No Garuda, reuses Phase 3 `sharp` photo normalizer, responsive 1–2 or 2x2 grid per page, editable caption per photo, and bottom-right certification signature (`ขอรับรองว่าเป็นเอกสารที่ถูกต้อง`).

### B. 2 Special Binder Items
8. **`EXTERNAL_FILE_SLOT` (ไฟล์แนบภายนอก / แผ่นคั่นเอกสารกระดาษ):**
   - Stores metadata (`title`, `externalDocNo`, `externalDate`, `stampReminderNote`, `copies`, optional uploaded PDF/image buffer path).
   - Export behavior toggle: `EMBED_UPLOADED_FILE` (merges actual PDF/image into binder) OR `PRINT_DIVIDER_CHECKLIST` (prints ink-saving checklist placeholder sheet).
9. **`LINKED_MODULE_REF` (ลิงก์งานจากเมนูจัดซื้อจัดจ้าง / พัสดุและครุภัณฑ์):**
   - Stores `{ targetModule: "PROCUREMENT" | "INVENTORY_REQUISITION" | "INVENTORY_ASSET_LOAN", targetId: string, includePdfInBinder: boolean }`.
   - Pulls **live** title, reference number (e.g. `สว ๑๘/๒๕๗๐` or `บว. ๐๒/๒๕๖๙`), date, total amount, and status directly from the target module so updating the procurement case immediately updates the Project Folder's roadmap!

## 3. Case Shared Variables & Live Cross-Reference Engine (`resolver.ts`)

### 3.1 Case-Level Shared Variables
Every `CaseFolder` has a key-value `variables` array (with common presets: `projectName`, `eventDate`, `eventLocation`, `budgetAmount`, `targetGroup`, plus custom user keys):
- Documents embed variables via tokens like `{{var.projectName}}` or `{{var.eventDate}}`.
- Updating a variable at the folder header updates every document inside the folder instantly.

### 3.2 Live Cross-Reference (`@ref`)
Any document can reference another item in the same folder using `{{ref:<itemId>:full}}` or `{{ref:<itemId>:short}}`:
- Example resolution of `{{ref:doc-02:full}}` pointing to an `INTERNAL_MEMO`:
  `"บันทึกข้อความ กองสวัสดิการสังคม ที่ ภก ๕๒๙๐๖/๑๕๑๐ ลงวันที่ ๓ ธันวาคม ๒๕๖๙ เรื่อง ขออนุมัติโครงการอบรมพัฒนาศักยภาพผู้สูงอายุ"`
- If the target item's running number or date is still blank:
  - In normal mode: renders `"..........."` (clean dotted fill-in line).
  - In `highlightBlanks: true` mode (Local Word Handoff): wraps unresolved tokens / blank fields with a structured `HighlightBlankRun` (rendered as **yellow highlight** in Word `<w:highlight w:val="yellow"/>` and pale amber badge in HTML preview) so an external colleague immediately spots what needs filling.

### 3.3 External Override Support (Round-Trip Word Editing)
Each `GENERATED_DOC` item supports an optional `externalOverride`:
```ts
externalOverride?: {
  fileName: string;
  fileType: "docx" | "pdf";
  storedPath: string;
  uploadedAt: string;
  note?: string; // e.g. "พี่ติ๋วแก้รายละเอียดหน้า 2 แล้ว"
}
```
When present, the roadmap preserves the document's order, number, and date, while clearly badging it as `"ใช้ฉบับแก้ไขภายนอก"` and bundling the overridden file during export.

## 4. Roadmap Validation Rules (`validator.ts`)

Reuse Phase 1 `holidays.ts` and numbering helpers to validate the entire folder:
1. **`REF_CHRONOLOGY_ERROR` (ERROR):** If Doc B contains `{{ref:A}}` and `docB.date < docA.date`, block and report exact conflict.
2. **`SAME_TRACK_NUMBER_ORDER` (ERROR):** Within the same numbering track (`INTERNAL_MEMO`, `EXTERNAL_LETTER`, `MUNICIPAL_ORDER`), items ordered later in the roadmap with earlier/duplicate running numbers trigger an error.
3. **`DATE_ON_HOLIDAY` (WARNING):** Warns with Thai weekday/holiday name + 1-click next working day suggestion.
4. **`UNRESOLVED_REFERENCE` (WARNING):** Warns if a referenced doc was deleted or still lacks a running number before export.
5. **`LINKED_MODULE_INCOMPLETE` (INFO/WARNING):** Surfaces summary alerts if a linked Procurement case or Inventory Requisition still has blocking errors or `PENDING_SIGNATURE` status.

## 5. Quick Blank Local Word Generator (`templates/blank-local-form.ts`)

Implement `buildBlankLocalWordForm(docType, agencyConfig, signatories, options)`:
- Supports all 7 official doc types (`INTERNAL_MEMO` .. `PHOTO_SHEET`).
- Pre-populates:
  - Official Garuda (correct size `1.5 cm` or `3.0 cm` per Sarabun spec)
  - Exact A4 margins & `TH Sarabun IT๙` (`16pt`) font rules
  - Latest `agencyConfig` header/phone/address and `signatories` chain
  - Clean yellow-highlighted placeholder prompts (`[พิมพ์ชื่อเรื่องที่นี่]`, `[พิมพ์เนื้อหาข้อเท็จจริง]`) when `highlightBlanks: true`, or clean dotted lines when `false`.
- Outputs a standalone `.docx` Buffer ready to send via LINE/Email to any colleague outside the system.

1. Changing a Case Variable (`eventDate`) updates both `INTERNAL_MEMO` and `EXTERNAL_LETTER` in the same folder.

3. Chronology violation (`docB.date < docA.date` when referencing A) triggers `REF_CHRONOLOGY_ERROR`.
