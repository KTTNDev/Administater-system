# Phase 4 · แบบฟอร์มจัดซื้อจัดจ้างกรอกครั้งเดียว

เปิดเมนูจัดซื้อจัดจ้างใน Workspace เดิม แล้วเลือก **เริ่มงานใหม่** ข้อมูลที่ทำด้วยระบบเดิมยังเปิดได้จาก **เปิดงานเดิม / ระบบเดิม** และลิงก์สัญญาเดิม `?view=procurement&case=…` ยังคงเปิดงานเดิม ไม่แปลงหรือลบข้อมูลเก่าโดยอัตโนมัติ

## วิธีใช้งาน

1. ตั้งข้อมูลหลักหน่วยงาน บุคลากร ผู้ลงนาม ร้านค้า และงบประมาณก่อน เพื่อเลือกใช้ในงานใหม่ได้
2. กรอกงานและงบ รายการและร้านค้า ผู้ตรวจรับ/ผู้ลงนาม เลขที่/วันที่ และผลตรวจรับ/รูปภาพ ข้อมูลใช้ร่วมกันทุกเอกสาร ราคา VAT และจำนวนเงินตัวอักษรคำนวณอัตโนมัติ
3. จองเลขในสมุดคุมตามการปฏิบัติงานจริง แล้วกรอกเลขทั้ง 5 ทะเบียนในลายแทง ปุ่มช่วยเติมเลขและวันทำการเติมเฉพาะช่องว่าง เลขประกาศแยกจากเลขหนังสือแจ้งผู้ชนะ
4. ตรวจคำเตือนด้านขวา คลิกเพื่อไปยังช่องที่เกี่ยวข้อง หรือใช้แก้ไขทันทีสำหรับวันหยุดและค่าปรับ วันครบกำหนดในเอกสารใช้วันทำการอยู่แล้ว ปุ่มยืนยันวันทำการไม่เปลี่ยนวันลงนามใบสั่ง
5. เลือกเอกสารในลายแทง 20 ตำแหน่งเพื่อดู A4 ส่วนเอกสารร้านค้า/LAAS/e-GP มีป้ายแหล่งที่มา เอกสาร e-GP ที่รองรับสามารถเลือก “ร่างเอง” ได้
6. ส่งออก PDF ทั้งแฟ้ม/ตามรอบ/เฉพาะฉบับ หรือ Word ZIP/เฉพาะฉบับ หากมีข้อผิดพลาดจะแสดงรายการก่อนส่งออกและต้องยืนยันฉบับร่างอย่างชัดเจน ข้อมูลจำเป็นที่ยังไม่ครบส่งออกไม่ได้แม้เลือกฉบับร่าง
7. เมื่อส่งออกชุดสำเร็จ เลือกบันทึกเลขลงทะเบียนเพื่อให้การเสนอเลขครั้งถัดไปเริ่มจากเลขล่าสุด

งานบันทึกอัตโนมัติหลังหยุดแก้ไขประมาณ 600 มิลลิวินาที มีปุ่มบันทึกและย้อนการแก้ไข 20 ครั้ง การคัดลอกปลอดภัยล้างเลข วันที่ อ้างอิงระบบ และรูปเก่าทั้งหมด พร้อมให้กรอกยอดเบิกสะสมใหม่ ปุ่มข้อมูลตัวอย่างสร้างงานที่มีป้าย `[ตัวอย่าง]` อย่างชัดเจน และลบได้

## การจัดหน้าและส่งออก

Preview โหลด HTML แบบ debounce 250 มิลลิวินาทีและยกเลิกคำขอเก่าที่ไม่ใช้แล้ว ฝังฟอนต์และรูปใน iframe แยกต่างหาก และใช้ `layout/paginate-document.ts` ร่วมกับ Chromium PDF เพื่อวัดพื้นที่จริงและแบ่งหน้า มีหมายเหตุใบต่อและเลขไทยบนหน้าถัดไป ปรับความหนาแน่นและขยาย 100% ได้ ความหนาแน่นที่เลือกส่งต่อไป PDF/Word ด้วย Word ยังคงเป็นเอกสารแก้ไขได้และอาจจัดหน้าใหม่เมื่อเปิดด้วยโปรแกรมหรือเครื่องพิมพ์อื่น

แผ่นคั่นบอกตำแหน่งเอกสารจากภายนอก ไม่ใช่ไฟล์หลักฐานต้นทางที่แนบมาจริง การเก็บหลักฐานและการส่งคลังที่ทำไว้ในระบบเดิมยังเข้าถึงได้จากงานเดิม

## การจัดเก็บและความเข้ากันได้

- API: `/api/procurement/workspace` ใช้การเข้าสู่ระบบและการตรวจ Origin แบบเดียวกับ API ส่งออก
- ตารางใหม่ใน SQLite เดิม: `procurement_domain_cases`, `procurement_domain_master`, `procurement_domain_registry` ไม่แตะตารางงานเดิม
- เก็บภาพที่ผ่านการหมุน/ย่อแล้วเป็น data URI ในร่าง จึงสำรองและย้ายเครื่องพร้อมข้อมูลได้
- เพิ่มทั้งสามตารางในระบบสำรองข้อมูล การกู้คืนที่ตรวจโครงสร้าง และการสำรองขึ้น Drive เดิม ไม่เก็บ OAuth หรือรหัสผ่านลงชุดสำรอง
- ป้องกันการเขียนทับจากหน้าต่างอื่นด้วยเลขเวอร์ชัน ทั้งงานและข้อมูลหลัก ทะเบียนรันเลขเพิ่มอย่างเดียว แยกประเภทและปี
- ร่างที่ยังไม่ครบใช้ schema แยกต่างหาก ไม่ลดข้อบังคับของ Phase 1 ที่ใช้ส่งออก
- ค่าเลือก PDF อยู่ในงานที่บันทึกและมีค่าที่จำไว้สำหรับงานใหม่ในเบราว์เซอร์

## การตรวจสอบ

รัน `npm run typecheck`, `npm test`, `npm run test:e2e`, `npm run build` ตามปกติ Unit tests รันทีละ worker เพื่อลดการใช้ RAM และ build ใช้ Webpack ที่มีมากับ Next.js หลังพบ Turbopack ใช้หน่วยความจำเกินเครื่องนี้

ระหว่างตรวจ build พบประกาศช่องโหว่ของ Next.js 16.4.2 จึงอัปเดตแพตช์ในสายเดียวกันเป็น 16.4.6 ตามผล npm audit โดย React ยังคงเป็น 19.2.8 เดิม

E2E เริ่ม production server ให้อัตโนมัติเมื่อมี build หรือ dev server เมื่อยังไม่มี build ที่พอร์ต 3100 ใช้ฐานข้อมูลใหม่ใต้ `output/e2e/<รอบ>/output/feature-check` เสมอ ไม่มี credentials ของผู้ใช้ และปิด server เมื่อทดสอบจบ หากกำหนด `PLAYWRIGHT_BASE_URL` เองจะไม่เริ่ม server ให้ ต้องเตรียมระบบทดสอบที่แยกจากงานจริงเอง

ชุด `tests/e2e/procurement-workflow.spec.ts` ทดสอบบิล 1,520/22,890 บาท การแก้ผู้ตรวจรับ การเลื่อนกำหนดส่งมอบวันหยุด การป้องกันเลขย้อน การคัดลอกปลอดภัย การบันทึกผ่าน reload และดาวน์โหลดไฟล์ PDF/ZIP จริง
