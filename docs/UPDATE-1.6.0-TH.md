# อัปเดตเป็นรุ่น 1.6.0 และการใช้ชุดพกพา

## เครื่องที่มีโฟลเดอร์โค้ดจาก Git อยู่แล้ว

ใช้ repository เดิมและ branch `codex/daily-workdesk` สำรองข้อมูลจากระบบและบันทึกงานก่อนอัปเดต หาก `git status` มีการแก้โค้ดในเครื่อง ให้จัดเก็บการแก้ไขนั้นก่อน ไม่ใช้ reset เพื่อลบทิ้ง

```powershell
.\Stop-Sarabun.cmd
git pull --ff-only origin codex/daily-workdesk
npm ci
npm run desktop:build
.\Open-Sarabun.cmd
```

ขั้นตอน build ต้องมี Node.js ตามข้อกำหนดของโครงการและ npm ในเครื่องพัฒนา ส่วนการเปิดชุดที่ build เสร็จแล้วใช้ Node.js ที่มากับชุดโปรแกรม

`git pull` รับความเปลี่ยนแปลงของโค้ดตามประวัติ Git ไม่ต้อง Clone ใหม่ การ pull อย่างเดียวไม่เปลี่ยนตัวโปรแกรมที่ `.desktop/current.json` ชี้อยู่ ต้อง build ให้สำเร็จก่อนเปิดรุ่นใหม่ ถ้า fast-forward ไม่ได้ ให้ตรวจความต่างก่อน ไม่ force pull หรือทับการแก้ไขในเครื่อง

ฐานข้อมูล `.env.local` เอกสารส่วนตัว แม่แบบ Word ที่ติดตั้งในระบบ และชุดโปรแกรมที่ build แล้วไม่อยู่ใน Git การ pull จึงไม่นำเอกสารใหม่จากอีกเครื่องมาด้วย หากเครื่องใหม่ยังไม่มีแม่แบบจัดซื้อ ให้ติดตั้งต้นฉบับที่ตรวจไว้หรือกู้จากชุดสำรองผ่านระบบ

## เครื่องที่มีเฉพาะชุดโปรแกรมพกพา

ชุดนี้ไม่จำเป็นต้องมีโฟลเดอร์ `.git` จึงไม่ใช้ `git pull` ให้นำชุดอัปเดตจากเครื่องพัฒนาไปใช้กับ `Update-Sarabun.cmd` ตามคู่มือเดิม ตัวอัปเดตตรวจ checksum สำรองข้อมูล และสลับรุ่นโปรแกรม ส่วนข้อมูลเดิมและค่าการเชื่อมต่อยังอยู่

## External drive และ flash drive

ระบบมี `Export-Sarabun.cmd` สำหรับสร้างชุดพกพาแบบรวมข้อมูล หลังหยุดระบบแล้วตัวส่งออกจะสร้าง snapshot ฐานข้อมูลด้วย `VACUUM INTO` ตรวจ integrity คัดลอกแฟ้มงาน และล้างตำแหน่งจัดเก็บเฉพาะเครื่องในสำเนา จึงควรใช้ชุดส่งออกนี้แทนการคัดลอกฐานข้อมูลระหว่างเปิดใช้งาน

ชุดที่ส่งออกเปิดด้วย `Open-Sarabun.cmd` บน Windows x64 ได้โดยไม่ต้อง Clone Git หรือติดตั้ง Node.js ใหม่ ยังต้องมี Edge/Chrome และ Microsoft Word สำหรับการจัดหน้าเอกสารจัดซื้อจากแม่แบบ รวมถึงฟอนต์ที่ต้นฉบับใช้ เช่น TH SarabunIT๙ หากฟอนต์นั้นไม่ได้ฝังในไฟล์ ชุดพกพาไม่ได้รวมสิทธิ์ใช้งานหรือโปรแกรม Microsoft Word ไว้ ควรเปิด PDF ทดสอบบนเครื่องปลายทางก่อนใช้จริง

ก่อนถอดไดรฟ์ ให้บันทึกงาน ใช้ `Stop-Sarabun.cmd` และนำอุปกรณ์ออกอย่างปลอดภัย ควรมีสำรองอีกตำแหน่ง เพราะไดรฟ์ที่ใช้ทำงานไม่ใช่สำรองของตัวเอง

รอบนี้ตรวจจากโค้ดการส่งออกและตัวเปิดโปรแกรม ยังไม่ได้ย้ายไปเสียบอุปกรณ์จริงหรือรับรองการเปลี่ยนอักษรไดรฟ์ทุกกรณี และยังไม่ได้เปลี่ยนพื้นที่ข้อมูลจริงของเครื่องปัจจุบัน

SQLite อธิบายวิธีสำรองที่รักษาความสอดคล้องของฐานข้อมูลและความเสี่ยงจากการคัดลอกระหว่าง transaction ไว้ที่ https://sqlite.org/backup.html และ https://sqlite.org/howtocorrupt.html
