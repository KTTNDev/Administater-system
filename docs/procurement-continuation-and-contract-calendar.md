# การแบ่งหน้าเอกสารและปฏิทินสัญญา

ปรับปรุง 16 พฤศจิกายน 2569

## เอกสารจัดซื้อจัดจ้าง

- D01–D14 ใช้ต้นฉบับ Word เดิมและข้อมูลกลางของงาน เพิ่มคำขึ้นต้นจากหน้าถัดไปพร้อม `...` ที่มุมขวาล่างของหน้าที่ยังมีเนื้อหาต่อ
- หน้าที่ 2 เป็นต้นไปมีเลขหน้าและหมายเหตุใบต่อ บันทึกข้อความใช้ “ใบต่อบันทึกข้อความ เรื่อง … ที่ … ลงวันที่ …” เอกสารประเภทอื่นใช้ “ใบต่อเอกสาร” และแสดงเฉพาะเลขที่/วันที่ที่มีจริงในเอกสารนั้น
- D11 ใช้วันที่ตรวจรับตามที่พิมพ์ในใบตรวจรับ ไม่ใช้วันที่บันทึกข้อความแทน ส่วน D04/D10 ไม่สร้างเลขที่หรือวันที่สมมติ
- คำนวณตำแหน่งจากการแบ่งหน้าจริงของ Microsoft Word และตรวจซ้ำหลังเพิ่ม footer เพื่อให้ตัวอย่าง PDF และไฟล์ Word ที่สร้างตรงกัน ช่องติ๊กไม่ถูกนำมาเป็นคำต่อหน้า
- ตัดเฉพาะย่อหน้าว่างท้ายเอกสารที่ไม่มีรูป กล่องข้อความ เขตข้อมูล หรือจุดอ้างอิงสำคัญ ป้องกันหน้าว่างท้ายฟอร์มเก่า และรักษาย่อหน้าในกล่องข้อความเดิม
- ตารางรายการ D07/D09 ทำซ้ำหัวตารางเมื่อขึ้นหน้าใหม่และไม่แยกแถวรายการเดียวข้ามหน้า
- ฝังฟอนต์ TH Sarabun New จากไฟล์ที่มีในโครงการลงใน Word โดยไม่ติดตั้งหรือเปลี่ยนฟอนต์ของ Windows และไม่แก้ตำแหน่งตราครุฑ/ลายเซ็นในต้นฉบับ
- ไฟล์เดิมที่บันทึกแล้วคงไว้ในประวัติ หากต้องการรูปแบบใบต่อรุ่นนี้ให้สร้างเอกสารรุ่นใหม่จากงานเดิม ไฟล์นำเข้าจากภายนอกไม่ถูกเปลี่ยนเอง
- หากนำ Word ออกไปแก้เนื้อหาจนตำแหน่งแบ่งหน้าเปลี่ยน ให้ตรวจคำต่อหน้าใหม่ หรือนำการแก้ไขกลับเข้าระบบแล้วสร้างใหม่ เนื่องจากคำต่อหน้าของชุดจัดซื้อจัดจ้างคำนวณจากเนื้อหาขณะสร้าง

## ร่างหนังสือทั่วไป

บันทึกข้อความ/หนังสือภายในในหน้าร่าง ตัวอย่าง PDF และไฟล์ Word มีหมายเหตุใบต่อหน้าที่ 2 เป็นต้นไป อ้างอิงเรื่อง เลขที่ และวันที่จากหนังสือเดียวกัน หน้าต้นฉบับของแต่ละชุดสำเนาไม่แสดงใบต่อ และไม่วางหมายเหตุหนังสือทับหน้าเอกสารแนบ

## บริหารสัญญา

1. เปิดงานจัดซื้อหรือจัดจ้าง แล้วเข้า “สัญญาและกำหนดเวลา” กำหนดวันครบสัญญาและรายการงานย่อย พร้อมผู้รับผิดชอบ วันครบกำหนด และงานที่ต้องเสร็จก่อน
2. บันทึกงาน ระบบใช้ข้อมูลงานนั้นแสดงในตารางบริหารสัญญาและหน้าปฏิทิน ทั้งชื่อเรื่อง ร้านค้า เลขอ้างอิง วงเงิน ผู้รับผิดชอบ และวันครบกำหนด
3. ปฏิทินมีรายการครบกำหนดสัญญาและกำหนดงานย่อย กดรายการเพื่อกลับไปส่วนสัญญาของงานเดิมได้โดยตรง
4. เมื่อแก้วันแล้วบันทึก ปฏิทินคำนวณจากข้อมูลล่าสุด จึงไม่มีรายการเก่าค้างหรือเหตุการณ์ซ้ำ ไม่สร้างแถวประชุมใหม่ลงตารางปฏิทิน
5. แสดงสถานะเกินกำหนด ครบกำหนดวันนี้ ใกล้ครบกำหนดภายใน 7 วันตามปฏิทิน รอดำเนินการ ยังไม่กำหนดวัน ตรวจรับแล้วรอดำเนินการคลัง และเสร็จงานแล้ว
6. ถือว่าส่งมอบ/ตรวจรับเสร็จเมื่อผลตรวจรับครบและงานย่อยทุกข้อเสร็จ ส่วนการปิดงานยังรอคลังลงรับรอบสองตามกระบวนงานเดิม สามารถเปิดตัวกรองดูรายการที่เสร็จแล้วได้

ระบบส่วนนี้เป็นการติดตามกำหนดเวลาที่ผู้ใช้บันทึก ยังไม่มีการเลื่อนวันอัตโนมัติตามวันหยุด ไม่มีการส่งข้อความแจ้งบุคคลภายนอก และไม่มีการเชื่อม API e-GP/e-LAAS

## หลักฐานการตรวจ

- `output/procurement-multipage`: งานจำลอง D01–D14 ทุกฉบับมี 3–4 หน้า รวม 44 หน้า ตรวจข้อความใบต่อ คำขึ้นต้นหน้าถัดไป ระยะห่าง และขนาด A4 พร้อมตรวจภาพทุกหน้า
- `output/procurement-long-bill`: บิลจำลอง 35 รายการ ตรวจว่ารายการอยู่ครบใน D04/D05/D07/D09
- `output/procurement-contract-calendar`: ทดสอบสร้างกำหนดเวลา เปลี่ยนวัน บันทึก เปิดจากปฏิทิน และหน้าจอมือถือโดยใช้ฐานข้อมูลทดสอบแยก
- ทดสอบข้อมูลจริงเฉพาะการอ่านและการเปิดฟอร์มที่ยังไม่บันทึก เปรียบเทียบข้อมูลธุรกิจ 16 ตารางกับสำรองก่อนติดตั้ง
