# จัดแฟ้มงานและย้ายที่เก็บข้อมูลในเครื่อง

รุ่นงานจัดเก็บ 6 พฤศจิกายน 2569

## ใช้งานตามปกติ

บันทึกร่างแล้วระบบจัดข้อมูลร่าง ไฟล์แนบ รูปแนบท้าย/รูปที่วางบนหน้า และสแกนฉบับลงนามไว้ในแฟ้มของหนังสือเรื่องนั้น เมื่อดาวน์โหลด PDF หรือ Word จะเก็บสำเนาไฟล์ที่ส่งออกในแฟ้มเดียวกันด้วย เอกสารในระบบและการจัดหน้าไม่ได้เปลี่ยน

ตัวอย่าง:

```text
พื้นที่เก็บข้อมูล/
├─ ฐานข้อมูล/sarabun.sqlite      ← มีเมื่อย้ายทั้งชุดผ่านระบบ
├─ หนังสือราชการ/
│  └─ หนังสือภายใน/
│     └─ ปีงบประมาณ 2570/
│        └─ ชื่อเรื่อง--รหัสประจำเรื่อง/
│           ├─ เอกสาร/          ← ข้อมูลร่าง.json และ PDF/Word ที่ส่งออก
│           ├─ ไฟล์แนบ/
│           │  ├─ ต้นฉบับ/
│           │  └─ สำหรับพิมพ์/
│           ├─ รูปภาพ/
│           ├─ ฉบับลงนาม/
│           └─ รายการไฟล์.json
├─ โครงการ/ปีงบประมาณ/ชื่อโครงการ/ขั้นตอน/งานย่อย/
├─ พัสดุและครุภัณฑ์/รายการพัสดุ หรือ รายการเบิกจ่าย/
├─ คลังกฎหมายและระเบียบ/หมวด/ปี/ชื่อกฎหมาย/
├─ ถังขยะ/ประเภทหนังสือ/ปีงบประมาณ/เรื่อง/
└─ สำรองข้อมูล/
```

ปีงบประมาณเต็ม 2570 คือ 1 ตุลาคม 2569 ถึง 30 กันยายน 2570 ใช้วันที่ของหนังสือ ไม่ใช่วันที่ดาวน์โหลด รหัสท้ายชื่อทำให้เรื่องชื่อเหมือนกันไม่เขียนทับกัน หากเปลี่ยนชื่อเรื่อง/ประเภท/วันที่ ระบบย้ายแฟ้มของเรื่องเดิมตามไปด้วย

- ที่ **ตั้งค่า → ที่เก็บและสำรองข้อมูล → แฟ้มงานในเครื่อง** ดูพาธที่ใช้อยู่ได้
- กด **จัดแฟ้มงานเดิม / ตรวจไฟล์อีกครั้ง** เพื่อจัดข้อมูลที่สร้างก่อนมีฟีเจอร์นี้ และลองใหม่หลังแก้ปัญหาดิสก์
- กด **เก็บ PDF หนังสือทั้งหมดในเครื่อง** หากต้องการสร้าง PDF ของร่างเดิมทั้งหมด ร่างที่จัดหน้าไม่ผ่านจะแสดงเหตุผลรายฉบับ
- การบันทึกร่างเก็บข้อมูลร่างและไฟล์ประกอบอัตโนมัติ แต่ไม่สร้าง PDF/Word ทุกครั้ง ต้องส่งออกเมื่อพร้อม
- เมื่อกดส่งออก รายงานพัสดุและรูปเล่มโครงการจะเก็บสำเนาตรงกับไฟล์ที่ดาวน์โหลดไว้ใน `ฉบับส่งออก` ตามรายละเอียดด้านล่าง การเปิดตัวอย่างรูปเล่มโครงการหรือ HTML แบบฟอร์มพัสดุอย่างเดียวไม่สร้างสำเนาส่งออก
- ฐานข้อมูลยังเป็นข้อมูลหลัก การแก้ไฟล์ JSON หรือ Word ในแฟ้มไม่แก้ร่างในระบบอัตโนมัติ หากเป็นฉบับลงนามให้แนบผ่านรายการหนังสือที่เกี่ยวข้อง
- ไฟล์ที่เคยแนบและรุ่นส่งออกเก่ายังเก็บไว้ในแฟ้ม แม้นำออกจากร่างแล้ว `รายการไฟล์.json` ระบุไฟล์ประกอบที่ใช้อยู่ปัจจุบัน อย่าลบแฟ้มรวมโดยไม่ตรวจว่ามีเอกสารอื่นใช้อยู่
- ไฟล์ที่ยังไม่ได้ผูกกับร่างและโฟลเดอร์ส่งออกเก่าคงอยู่ เพื่อไม่ลบสิ่งที่อาจยังใช้งาน
- การจัดแฟ้มในเครื่องและการส่งขึ้น Drive เป็นคนละขั้นตอน ดูผลสำเร็จรายไฟล์ที่ส่วนแฟ้มงานบน Google Drive

## ซิงก์แฟ้มงานไป Google Drive

1. เชื่อมบัญชีและกำหนดโฟลเดอร์ปลายทางในหมวด **Google Drive**
2. เปิด **ตั้งค่า → ที่เก็บและสำรองข้อมูล → แฟ้มงานบน Google Drive**
3. กด **เตรียมรายการจากแฟ้มในเครื่อง** ระบบรวบรวมไฟล์ที่ผูกกับเรื่องปัจจุบัน ยังไม่ส่งไฟล์ในขั้นนี้
4. กด **เริ่มซิงก์แฟ้มงาน** เปิดหน้านี้ไว้จนเสร็จ ดูจำนวนสำเร็จและเปิดรายเรื่องดูผลแต่ละไฟล์ได้
5. หากหยุดหรือเน็ตขาด ให้กลับหน้าดังกล่าวแล้วกด **ทำต่อ / ลองไฟล์ที่ค้างใหม่** ผลสำเร็จเก่ายังอยู่ ระบบตรวจไฟล์บน Drive ก่อนข้ามรายการเดิม
6. เมื่อแก้ร่าง แนบไฟล์เพิ่ม หรือเปลี่ยนชื่อเรื่อง ให้กด **เตรียมรายการจากแฟ้มในเครื่อง** ใหม่ก่อนซิงก์

เป็นการสั่งซิงก์เอง ยังไม่ส่งขึ้น Drive อัตโนมัติทุกครั้งที่แก้ไข ระบบแบ่งส่งเป็นชุดสั้น ๆ ปุ่มหยุดจะหยุดหลังชุดปัจจุบัน ไม่ดึงไฟล์ที่ส่งแล้วกลับลงมา

- โฟลเดอร์รายเรื่องรวมข้อมูลร่าง ต้นฉบับ/ไฟล์แปลงสำหรับพิมพ์ รูปภาพ ฉบับลงนาม และ PDF/Word รุ่นปัจจุบันที่เคยส่งออก โครงการ พัสดุ และคลังกฎหมายมีแฟ้มของตนเอง
- เอกสารลับและรายการในถังขยะไม่เข้าแผนซิงก์นี้ ไฟล์เก่าที่ไม่ผูกกับเรื่องหรือไฟล์ที่ใส่เพิ่มเองในโฟลเดอร์ไม่ได้ส่งขึ้นอัตโนมัติ
- การซิงก์เป็นสำเนาแฟ้มงาน รวมร่างที่ยังไม่ตรวจทาน ไม่เปลี่ยนสถานะเป็นเอกสารราชการฉบับส่งออก ไม่ออกเลขให้ และไม่เปลี่ยนการตรวจทานเดิม
- สำเร็จหมายถึง Drive ยืนยันขนาดและ checksum ตรงตอนตรวจ ไม่ใช่แค่จองรหัสไฟล์ไว้ หากตรวจพบผู้แก้ไฟล์บน Drive ระบบไม่เขียนทับและแสดงข้อผิดพลาดให้ตรวจสอบ
- ระบบไม่ลบรุ่นเก่าหรือไฟล์ที่นำออกจากร่างบน Drive อัตโนมัติ จึงอาจพบประวัติไฟล์หลายรุ่นในเรื่องเดียวกัน
- หากบัญชีอ่านสิทธิ์แชร์ไม่ได้ จะมีข้อความแจ้ง ให้เจ้าของโฟลเดอร์ตรวจสิทธิ์ใน Drive เอง หากตรวจพบแชร์สาธารณะหรือทั้งโดเมน ระบบไม่เริ่มซิงก์
- ปุ่มสำรองฐานข้อมูลเดิมยังจำเป็นสำหรับงานทั้งระบบ เช่น To-do ทะเบียนหนังสือ และข้อมูลที่ไม่ได้เป็นไฟล์รายเรื่อง แฟ้มบน Drive ไม่ใช่ชุดกู้คืนฐานข้อมูลทั้งระบบ

หมวดอังกฤษจากรุ่นก่อนจะย้ายเป็นชื่อไทยเมื่อจัดแฟ้มทั้งชุด ไฟล์ส่งออกเก่าที่หาเรื่องต้นทางได้อยู่ใน **เอกสาร/ฉบับส่งออกเดิม** ส่วนที่ยังระบุเรื่องไม่ได้อยู่ใน **ฉบับส่งออกเดิมที่ยังไม่ผูกกับเรื่อง/ปีปฏิทิน ...** โดยคงเนื้อหาและไม่เขียนทับไฟล์ชื่อชนกัน ชื่อเรื่องที่ผู้ใช้ตั้งเป็นภาษาอังกฤษยังคงเดิม

## ย้ายที่เก็บทั้งหมด

1. หยุดกรอกในหน้าต่างอื่นชั่วคราว เปิด **ตั้งค่า → ที่เก็บและสำรองข้อมูล**
2. เปิด **เปลี่ยนโฟลเดอร์ข้อมูลทั้งชุด** กด **Browse…** แล้วเลือกโฟลเดอร์ว่างบนเครื่อง หรือพิมพ์พาธเต็ม เช่น `D:\ข้อมูลสารบรรณ`
3. กด **ตรวจสอบก่อนย้าย** ตรวจต้นทาง ปลายทาง ขนาด และพื้นที่ว่าง
4. ติ๊กยืนยันตำแหน่ง แล้วกด **ย้ายข้อมูลไปโฟลเดอร์นี้** รอผลสำเร็จ ไม่ปิดโปรแกรมระหว่างย้าย
5. ตรวจพาธฐานข้อมูลและแฟ้มงานที่เปลี่ยนไป เปิดร่างเดิมและใช้งานต่อได้

ระบบล็อกการเขียนฐานข้อมูลเดิมชั่วคราว สร้างสำเนาที่รวมข้อมูลล่าสุดใน WAL ตรวจไฟล์ด้วย SHA-256 ตรวจ SQLite และจัดแฟ้มปลายทางก่อนสลับที่เก็บ ฐานข้อมูลเดิมจะชี้ไปตัวใหม่และป้องกันการเขียนทับ เพื่อไม่แยกข้อมูลเป็นสองชุด โปรแกรมรุ่นนี้และเครื่องมือส่งออก/อัปเดตจะตามตำแหน่งใหม่ได้

พาธใหม่บันทึกใน `.env.local` เป็น `DATABASE_PATH` และ `DATABASE_REQUIRE_EXISTING=true` หากตำแหน่งใหม่หายไป โปรแกรมจะหยุดแจ้งข้อผิดพลาด ไม่สร้างฐานข้อมูลว่างมาทับงาน หากใช้ไดรฟ์ภายนอกต้องเชื่อมต่อไดรฟ์นั้นก่อนเปิดโปรแกรม

ปลายทางต้องว่างและไม่ซ้อนกับที่เก็บเดิม ถ้าย้ายไม่สำเร็จก่อนสลับฐานข้อมูล ชุดเดิมยังใช้งานได้ อาจมีสำเนาบางส่วนที่ปลายทาง ให้เลือกโฟลเดอร์ว่างใหม่หรือให้ผู้ดูแลตรวจสำเนาค้างก่อนลองใหม่ ระบบไม่ลบสำเนาค้างเอง

## สำรอง ย้ายเครื่อง และกู้กรณีผิดปกติ

- สำรองข้อมูลตามเมนูเดิมยังเก็บข้อมูลธุรกิจและไฟล์แนบจากฐานข้อมูลได้ครบ
- ชุดโปรแกรมพกพาแบบรวมข้อมูลจะนำฐานข้อมูลปัจจุบันและแฟ้มงานไปด้วย รวม PDF/Word ที่เก็บไว้ ชุดโปรแกรมมีค่าการเชื่อมต่อส่วนตัว ต้องเก็บเป็นส่วนตัว
- ชุดสำรองข้อมูลธุรกิจไม่ใช่สำเนาทุกไฟล์ที่เพิ่มเองในแฟ้ม รวมถึง Word ที่แก้จากภายนอก ควรสำรองโฟลเดอร์แฟ้มงานควบคู่ด้วย
- หลังย้าย อย่าเปิดฐานข้อมูลเก่าเพื่อทำงานต่อ และอย่าลบฐานข้อมูลเก่า/จุดย้อนกลับจนตรวจชุดใหม่และสำรองเรียบร้อย
- ถ้าต้องการกลับพื้นที่เดิมหลังใช้งานชุดใหม่แล้ว ให้ย้าย **ข้อมูลล่าสุด** ผ่านหน้าตั้งค่าไปโฟลเดอร์ว่างอีกแห่ง ไม่กู้สำเนาเก่าทับงานใหม่
- จุดย้อนกลับเฉพาะเครื่องอยู่ `output/data-migrations/<เวลา-รหัส>/` ใต้โฟลเดอร์โปรแกรม มี `original.sqlite`, `original.env`, `next.env`, `result.json` จำกัดสิทธิ์ผู้ใช้ปัจจุบันและ SYSTEM ไฟล์เหล่านี้มีค่าลับ ห้ามขึ้น GitHub หรือแชร์
- การกู้จุดย้อนกลับใช้สำหรับเหตุผิดปกติขณะย้าย: หยุดโปรแกรมก่อน เก็บสำเนาข้อมูลปัจจุบันทั้งหมด จากนั้นให้ผู้ดูแลกู้ `original.sqlite` และค่าจาก `original.env` พร้อมตรวจข้อมูลใหม่ที่อาจเกิดภายหลัง ห้ามแทนที่ขณะโปรแกรมทำงาน

## จุดต่อยอดสำหรับผู้พัฒนา

- `scripts/workspace-files.mjs`: กฎชื่อแฟ้ม ปีงบประมาณ เจ้าของไฟล์ และการเขียนสำเนา ใช้ร่วมกันในแอปและเครื่องมือย้ายข้อมูล
- `src/lib/local-dossiers.ts`: เชื่อมฐานข้อมูลกับแฟ้ม จับข้อผิดพลาดโดยไม่ย้อนการบันทึกข้อมูลที่สำเร็จ และแจ้งรายการที่ต้องลองใหม่
- `scripts/migrate-data-location.mjs`: ตรวจแผน ล็อก/สำรอง คัดลอก ตรวจ และเปลี่ยนที่เก็บ
- `scripts/data-location.mjs` / `src/lib/db.ts`: ตามตำแหน่งฐานข้อมูลใหม่และเชื่อมต่อใหม่
- `src/app/data-location-actions.ts`: ตรวจผู้ใช้/คำขอจากเครื่องเดียวกัน สร้างแผนย้ายอายุ 10 นาที และเรียกหน้าต่าง Windows
- `src/components/data-location-settings.tsx`: หน้าตรวจแผน/ยืนยัน/รายงานผล
- `scripts/dossier-sync-plan.mjs`: รวบรวมเฉพาะไฟล์ที่มีเจ้าของและตรวจ hash ก่อนส่ง
- `scripts/dossier-drive.mjs`: โฟลเดอร์/รหัสคงที่ การอัปโหลด และตรวจ checksum ฝั่ง Drive
- `src/lib/dossier-sync.ts`: คิวถาวร ล็อกงาน ตรวจสิทธิ์และสถานะรายไฟล์
- `src/components/dossier-sync-settings.tsx`: หน้าควบคุมและติดตามผล
- `tests/dossier-sync.test.ts` และ `tests/e2e/dossier-sync.spec.ts`: การส่งซ้ำ เครือข่ายขาด และใช้งานผ่านหน้าจอ
- `tests/data-location.test.ts` และ `tests/e2e/data-location.spec.ts`: การย้าย ไฟล์หาย พาธซ้อน ไฟล์ชน การรักษาไบนารี และใช้ต่อผ่านหน้าจอ

อย่าเพิ่มตารางหรือไฟล์ชนิดใหม่โดยตรวจเพียงหน้าอัปโหลด ต้องตามให้ครบ: เจ้าของไฟล์ → จัดแฟ้ม → สำรอง/กู้คืน → ส่งออกชุดย้ายเครื่อง → แผนซิงก์และการตรวจ Drive


## สำเนารายงานพัสดุและรูปเล่มโครงการ

| ผลงานที่ส่งออก | ตำแหน่งใต้โฟลเดอร์แฟ้มงาน |
| --- | --- |
| รูปเล่มโครงการ PDF / Word | โครงการ / ปีงบประมาณ / ชื่อโครงการ / ฉบับส่งออก |
| ใบรายการรับ–เบิก–ยืม PDF | พัสดุและครุภัณฑ์ / รายการเบิกจ่าย / ปีงบประมาณ / เลขรายการ / ฉบับส่งออก |
| แบบฟอร์มพัสดุที่แก้ไขเอง PDF / Word | พัสดุและครุภัณฑ์ / แบบฟอร์มพัสดุ / ปีงบประมาณ / ชื่อร่าง / ฉบับส่งออก |
| ทะเบียนเคลื่อนไหว / รายงานวิเคราะห์ PDF / CSV | พัสดุและครุภัณฑ์ / รายงานตามช่วงเวลา / ปีงบประมาณหรือช่วงหลายปี / ชื่อรายงานและช่วงวันที่ / ฉบับส่งออก |

ใช้ปุ่มส่งออกเดิมได้เลย ระบบจะเก็บสำเนาเพิ่มโดยไม่เปลี่ยนรูปแบบเอกสาร จำนวนสต็อก หรือสถานะงาน เมื่อส่งออกใหม่จะเก็บไฟล์รุ่นก่อนเอาไว้ และ `ข้อมูลการส่งออก.json` ระบุข้อมูลรุ่นต้นทาง เงื่อนไขค้นหา ช่วงวันที่ และรายการฉบับล่าสุดต่อรูปแบบ

- รายงานต่างช่วงวันที่ คำค้น หรือหมายเหตุ แยกแฟ้มกัน ไม่เขียนทับรายงานอีกชุด
- หากแก้ข้อมูลระหว่างสร้างไฟล์ ระบบจะแจ้งให้ส่งออกใหม่เพื่อไม่ผูกไฟล์กับข้อมูลผิดรุ่น
- รูปเล่มโครงการ ใบรายการ และแบบฟอร์มที่ต้นทางเปลี่ยน จะไม่ถูกส่งไป Drive ในฐานะฉบับล่าสุดจนกว่าจะส่งออกใหม่ ไฟล์เก่าในเครื่องยังอยู่
- รายงานตามช่วงเวลาเป็นภาพข้อมูล ณ ตอนที่สร้าง ยังคงเก็บและซิงก์ได้แม้มีรายการใหม่ภายหลัง ตรวจช่วงวันที่และเวลาสร้างได้ในข้อมูลการส่งออก
- Drive ยังใช้คำสั่ง **เตรียมรายการจากแฟ้มในเครื่อง → เริ่มซิงก์แฟ้มงาน** การส่งออกไม่ได้เริ่มอัปโหลดเอง
- หากที่เก็บเขียนไม่ได้ ระบบไม่แจ้งว่าส่งออกและเก็บสำเนาสำเร็จ ให้แก้ที่เก็บแล้วกดส่งออกใหม่ ข้อมูลต้นทางยังอยู่

การย้ายที่เก็บทั้งชุดและชุดโปรแกรมพกพาพาสำเนารายงานไปด้วย ส่วนคำสั่งสำรองฐานข้อมูลธุรกิจเก็บข้อมูลต้นทางและไฟล์แนบ ไม่รวมสำเนารายงานที่สร้างในโฟลเดอร์เหล่านี้ หากต้องเก็บฉบับส่งออกเดิมด้วย ให้ซิงก์แฟ้มขึ้น Drive หรือย้าย/คัดลอกโฟลเดอร์แฟ้มงานทั้งชุดร่วมกับฐานข้อมูลสำรอง
