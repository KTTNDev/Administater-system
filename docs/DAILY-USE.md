# เปิดระบบสำหรับใช้งานประจำ

## โหมดพัฒนา
ดับเบิลคลิก `Open-Sarabun.cmd` ใช้แก้ไขและทดสอบบนเครื่องนี้

## โหมดใช้งานประจำ
1. ตั้งค่า `APP_PASSWORD` อย่างน้อย 12 ตัวอักษร และ `SESSION_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษรใน `.env.local` ห้ามส่งค่าทั้งสองขึ้น GitHub
2. ใช้ `APP_URL=http://127.0.0.1:3000` สำหรับตัวเปิดบนเครื่องนี้
3. รัน `npm run build` หลังเปลี่ยนโค้ด
4. ปิดเซิร์ฟเวอร์โหมดพัฒนาก่อน แล้วดับเบิลคลิก `Open-Sarabun-Production.cmd`
5. เข้าสู่ระบบด้วยรหัสผ่านที่ตั้งไว้

ตัวเปิดตรวจโหมดของเซิร์ฟเวอร์ที่พอร์ต 3000 หากคนละโหมดจะหยุดพร้อมข้อความ ไม่สั่งปิดโปรแกรมอื่นให้โดยอัตโนมัติ บันทึกการเริ่มระบบอยู่ `output/logs` กรณีไม่มี Chrome จะเปิดเบราว์เซอร์เริ่มต้น

ทดสอบ production login ด้วยฐานข้อมูลจำลองแยกแล้ว: ไม่ข้ามการล็อกอินแม้ LOCAL_DEMO=true, ปฏิเสธรหัสผ่านผิด, รับรหัสผ่านถูกต้อง แต่เครื่องใช้งานจริงยังต้องตั้งรหัสผ่านก่อน ระบบปัจจุบันเป็นบัญชีผู้ปฏิบัติงานร่วม ยังไม่ใช่ระบบหลายบัญชี

## สำรองและกู้คืน
หน้าตั้งค่าหน่วยงานและ Drive → พื้นที่จัดเก็บและซิงก์ → ส่งออกข้อมูลทั้งหมดในเครื่อง จากนั้นกดโหลดรายการชุดสำรอง → ตรวจและกู้คืน

ระบบตรวจ checksum/SQLite integrity แล้วกู้ลงโฟลเดอร์ใหม่ พร้อมแสดงพาธให้คัดลอก ไม่สลับฐานข้อมูลจริงอัตโนมัติ และไม่คืนรหัสผ่านหรือ OAuth ดูรายละเอียดใน BACKUP-RESTORE.md

## Google Drive
ยังต้องมี OAuth client แบบ Web application ของบัญชีเจ้าของระบบ โดย callback ตรงกับ `http://127.0.0.1:3000/api/google/callback` ใช้เครื่องมือเดิม `node scripts/setup-google-oauth.mjs "พาธไฟล์ JSON"` เพื่อนำเข้าบนเครื่อง จากนั้นเริ่มเซิร์ฟเวอร์ใหม่และเชื่อมบัญชีจากหน้าตั้งค่า การมี Drive connector ในแชทไม่ได้เชื่อมบัญชีให้แอป
