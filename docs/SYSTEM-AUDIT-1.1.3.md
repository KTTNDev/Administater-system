## การเลื่อนฟอร์ม

พบและแก้ปัญหาที่ใช้โครงสร้างร่วมกันทั้ง 13 แบบ:

- [x] ความกว้าง 801–1,000 พิกเซลแสดงตัวอย่างก่อนช่องกรอก เพราะจุดเปลี่ยนหน้าจอในสไตล์สองไฟล์ไม่ตรงกัน
- [x] แถบทางลัดหายเมื่อเลื่อนหน้าต่างแคบ เพราะอยู่ในกล่อง overflow ที่ไม่มีพื้นที่ให้เลื่อนจริง
- [x] กดทางลัดแล้วไม่ถึงหัวข้อ เพราะเลือกกล่องดังกล่าวแทนพื้นที่เลื่อนของหน้า
- [x] จัดให้ช่องกรอกอยู่ก่อนตัวอย่างในหน้าต่างแคบ และให้หน้าเป็นผู้ควบคุมการเลื่อนแนวตั้ง
- [x] ทดสอบด้วยเมาส์ทั้งลงสุดหน้า กลับขึ้นต้นหน้า ไปส่วนท้าย ไปตรวจทาน และกลับส่วนหัว
- [x] ตรวจทั้งความกว้าง 1,440 / 960 / 868 / 390 พิกเซล และตัวอย่างเอกสารหลายหน้า
- [x] ตรวจซ้ำในหน้าระบบที่ผู้ใช้เปิดอยู่: ทางลัดติดบนจอ และส่วนท้ายอยู่ใต้แถบโดยไม่ถูกบัง

ไม่ได้เปลี่ยนสัดส่วนกระดาษ รูปแบบหนังสือ หรือการจัดหน้า PDF/Word ในการแก้การเลื่อนครั้งนี้

## หลักฐานการตรวจ

- Unit tests: 126 รายการผ่านใน 30 ไฟล์
- การสร้างโปรแกรม: ผ่าน Next.js 16.4.0 และ TypeScript
- npm audit หลังอัปเดต: ไม่พบช่องโหว่ที่รู้จักในรายการที่ตรวจ ณ วันที่ตรวจ ไม่ใช่การรับรองความปลอดภัยทุกกรณี
- E2E ผ่านครบ 165 กรณีบนโปรแกรมชุดเดียวกัน โดยแบ่งตรวจเป็น 18 กรณีวงจรเอกสาร/หน้าระบบ, 59 กรณีการเลื่อน/มุมมองใหม่ และ 88 กรณีที่เหลือ
- บันทึกผล: output/comfort-verification.log (18 กรณีแรก), output/comfort-scroll-final.log (59 ผ่าน) และ output/comfort-regression-final.log (88 ผ่าน)
- ทดสอบการวางหน้าระบบทั้ง 10 หน้าที่ความกว้าง 320 / 375 / 414 / 768 พิกเซล และตรวจภาพที่ขนาด 1,440 พิกเซล
- สีหลักของข้อความ ปุ่ม และวงโฟกัสผ่านเกณฑ์ความต่างสีที่ตรวจ: output/comfort-contrast.json
- ชุดอัปเดต 1.1.3 ตรวจแฮชครบ 2,226 ไฟล์ และตรวจ ZIP ไม่พบฐานข้อมูลหรือค่าลับของเครื่อง
- ภาพและ PDF จำลอง: output/system-audit และ output/scroll-fixed-*.png (ไม่อัปโหลดข้อมูลทดสอบเข้า Git)

หมายเหตุการตรวจ: รอบก่อนหน้าพบการรอดาวน์โหลด PDF เกินเวลา 60 วินาทีเป็นครั้งคราว แต่ไม่เกิดซ้ำในการตรวจรุ่นสุดท้าย จึงยังไม่สรุปสาเหตุ หากเกิดซ้ำให้เก็บสถานะคำขอและข้อความผิดพลาดประกอบการตรวจ
