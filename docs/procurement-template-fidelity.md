# D07 จากต้นฉบับและผลตรวจความเหมือน

15 พฤศจิกายน 2569

อัปเดตตามคำยืนยันผู้ใช้: รูปแบบต้นฉบับผ่านความเห็นชอบแล้ว ตัวอักษรสีแดงเดิมมีไว้เตือนให้แก้ จึงเปลี่ยนเป็นสีดำในฉบับใช้งาน (`D07-black-v1`) ทั้ง Word และ PDF ข้อมูลที่กรอกไว้เดิมคงอยู่ ทดสอบ 9 กรณีผ่าน และตรวจภาพ PDF ฉบับใช้งานแล้วไม่พบพิกเซลสีแดง ต้นฉบับอ้างอิงยังคงเดิมเพื่อเทียบ ป้ายและลิงก์ดาวน์โหลดแยกชัดเจน ผลเทียบ 0 พิกเซล/ทุกไบต์ด้านล่างเป็นหลักฐานก่อนปรับสี ความต่างสีดำรอบนี้เป็นการแก้ที่ผู้ใช้อนุญาต ไม่กล่าวอ้างว่าฉบับสีดำยังมีไบต์เหมือนต้นฉบับสีแดง

เปิดหน้าใหม่ที่ <http://127.0.0.1:3107/procurement/template> ขณะเซิร์ฟเวอร์ห้องทดลองทำงาน หน้านี้ใช้สำเนา `7.รายงานพิจารณาผล.docx` เป็นแม่แบบจริง แก้เฉพาะข้อความในตำแหน่งเดิม และแสดงหน้าที่เรนเดอร์จาก Word ฉบับที่ดาวน์โหลดได้ โดยใช้ Microsoft Word บนเครื่องนี้ ไม่สร้างหัวหนังสือ ตาราง หรือช่องลงนามด้วย HTML ใหม่

## ผลที่ตรวจแล้ว

- ข้อมูลเดิม: ไฟล์ Word ที่ได้ตรงกับต้นฉบับทุกไบต์ SHA-256 `3b6d0541a216951bf48f0e51f8c227aa34ab947f8ab6646083bd4fc818a7ef31` เรนเดอร์เป็น PDF ด้วย Word แล้วเทียบภาพ 120 dpi ทุกหน้า พบความต่าง 0 พิกเซล ทั้งคู่มี 1 หน้า
- แก้ตัวอย่าง 7 ช่อง: เลขหนังสือ ชื่อร้าน ราคาที่ตกลง และชื่อผู้ลงนามทั้ง 4 จุด ผลยังมี 1 หน้า ตราครุฑเทียบภาพแล้วยังตรงเดิม ตรวจภาพครบหน้าแล้ว ไม่มีข้อความทับหรือถูกตัดในตัวอย่างนี้
- โครงสร้าง: ส่วนประกอบไฟล์อีก 18 ส่วนไม่เปลี่ยนไบต์ รวมรูปครุฑ ฟอนต์/สไตล์ ตารางที่ประกาศใน XML หัวท้ายกระดาษ และความสัมพันธ์ไฟล์ ใน `word/document.xml` เปลี่ยนเฉพาะเนื้อความของ `w:t` ที่กำหนดไว้ แท็ก รูปแบบ ย่อหน้า แท็บ กริดตาราง เซลล์ผสาน กล่องข้อความและตำแหน่งยึดยังคงเดิม อัปเดตชื่อใน Choice และ Fallback ให้ตรงกัน
- หน้าเว็บจริง: กรอก สร้างตัวอย่าง สลับต้นฉบับ/ฉบับล่าสุด ดาวน์โหลด บันทึกและโหลดใหม่ผ่าน ตรวจว่าภาพโหลดจริงด้วยขนาดมากกว่า 900 พิกเซล ไม่มีข้อผิดพลาด JavaScript และหน้าจอ 390 พิกเซลไม่ล้นแนวนอน
- TypeScript ผ่าน ทดสอบฟังก์ชันเดิมและตัวเติมแม่แบบรวม 9 กรณีผ่าน
- ไฟล์ต้นฉบับบน Desktop ยังมีไบต์เหมือนก่อนดำเนินงาน เปิด Word เฉพาะสำเนาในห้องทดลองแบบอ่านอย่างเดียว ไม่มีการบันทึกทับต้นฉบับ

## วิธีทดลอง

1. เปิดหน้าใหม่และเลือก “ต้นฉบับอ้างอิง” เพื่อดูแบบที่ส่งมา
2. เปลี่ยนชื่อร้าน เลขหนังสือ วันที่ หรือชื่อผู้ลงนาม แล้วกด “สร้างตัวอย่างและบันทึก”
3. สลับดู “ฉบับที่สร้างล่าสุด” ตรวจตำแหน่งและข้อความ แล้วดาวน์โหลด Word หรือเปิด PDF เพื่อพิมพ์ A4
4. “คืนข้อมูลต้นฉบับ” เติมค่าเดิมลงฟอร์มและเปิดภาพอ้างอิง กดสร้างอีกครั้งหากต้องการบันทึกค่าเดิมเป็นฉบับล่าสุด

ข้อมูลตั้งต้นคงค่าที่อยู่ในไฟล์ตัวอย่าง รวมถ้อยคำเก่าที่ต้องทบทวน ไม่ตีความว่าค่าทั้งหมดเป็นข้อมูลงานจริงที่ตรวจรับแล้ว

## ขอบเขตของผลตรวจ

ความตรงทุกไบต์และ 0 พิกเซลเป็นผลสำหรับ **กรณีข้อมูลเดิมบนเครื่องนี้** การแก้ 7 ช่องเป็นตัวอย่างที่ตรวจเพิ่มแล้ว ไม่ใช่การรับรองว่าข้อความยาวใด ๆ จะอยู่หน้าเดียวเสมอ

ขณะนี้เปิดให้แก้ 24 ช่องในย่อหน้า/แถวเดิม ภาษียึดแบบต้นฉบับที่รวม VAT 7% ในราคาตกลงและคำนวณฐาน/ภาษีจากยอดเดียวกัน ยังไม่มีการเพิ่มรายการตาราง เพิ่มย่อหน้า เปลี่ยนนโยบายภาษี หรือขยับช่องลงนามอิสระ ส่วนเหล่านี้ต้องมีแม่แบบและการตรวจเพิ่ม ไม่บังคับย่อฟอนต์ให้จบหน้าเดียว

ข้อความใบต่อเก่าของต้นฉบับยังคงอยู่ในไฟล์เพื่อพิสูจน์ฐานความเหมือน และไม่แสดงในหน้าแรกตามการตั้งค่าของต้นฉบับ ต้องแก้ให้สัมพันธ์กับเรื่อง/เลข/วันที่และทดสอบเอกสารหลายหน้าเป็นขั้นถัดไป หากจำนวนหน้าเปลี่ยน หน้าเว็บจะแจ้งว่าต้องตรวจการตัดหน้า ช่องลงนาม และใบต่อก่อนใช้

Word จากหน้าใหม่นี้ยังไม่เชื่อมการนำกลับมาตรวจความต่าง ส่วนการเทียบสามรุ่นที่ทำไว้ในห้องทดลองเดิมยังอยู่แยกกัน ต้องเชื่อมให้รักษาแม่แบบต้นฉบับด้วยก่อนใช้งานทั้งกระบวนงาน

การเรนเดอร์ในช่วงทดลองนี้ต้องใช้ Microsoft Word ที่ติดตั้งบน Windows และ Poppler สำหรับแสดงภาพ การสร้างตัวอย่างเกิดเมื่อกดปุ่ม มีการเก็บผลตามรหัสเนื้อหาเพื่อใช้ซ้ำ ไม่มีการอัปโหลดเอกสารไปบริการภายนอก ยังเป็นห้องทดลองแยกจากข้อมูลจริงและการสำรองข้อมูลของแอปหลัก
