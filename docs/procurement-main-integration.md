# เชื่อมจัดซื้อจัดจ้างเข้าระบบหลัก — ขั้นแรก

> รุ่นปัจจุบันดู [กระบวนงานครบชุด D01–D14 ถึงคลังลงรับรอบสอง](procurement-full-process.md) พร้อมฟอร์มกะทัดรัดและเงินตัวอักษรอัตโนมัติ รายละเอียดต่อไปนี้เก็บผลขั้นแรกไว้เป็นประวัติ

อัปเดตรอบถัดมา: เพิ่ม [ร่างคู่ preview อัตโนมัติ ข้อความตั้งต้น และ D01](procurement-live-preview-and-samples.md) พร้อมคำบอกใต้ช่องว่าข้อมูลแสดงที่เอกสารใด รายละเอียดด้านล่างเก็บผลเชื่อมขั้นแรกไว้เป็นประวัติ

เพิ่มเติมตามคำยืนยันล่าสุด: [แยกชุดเอกสารตามประเภทหนังสือเดิมทั้ง 13 แบบ](procurement-document-families.md) และใช้ตัวแบ่งพื้นที่ EditorLayout ร่วมกับหน้าร่างหนังสือหลัก

วันที่ตรวจ: 15 พฤศจิกายน 2569

## สิ่งที่เชื่อมแล้ว

- เมนู `จัดซื้อจัดจ้าง` ใน Workspace หลัก และ URL `/?view=procurement` ใช้การเข้าสู่ระบบและฐานข้อมูลชุดเดียวกับระบบหลัก
- แยกงานซื้อ/จ้าง บันทึกข้อมูลกลางของแต่ละเรื่อง เลขบิล ประเภทหลักฐาน แนวทางดำเนินการ และวันครบกำหนดสัญญา
- เรียงงานตามวันครบกำหนดสัญญา เป็นการจัดลำดับเบื้องต้น ยังไม่ใช่ปฏิทินงานตามเงื่อนไขสัญญาหรือระบบแจ้งเตือน
- แยกแนวทางจัดซื้อจัดจ้างจากข้อยกเว้น e-GP ว322 พร้อมคำเตือนเรื่องเงื่อนไข ว119/ว804 และวงเงินต่ำกว่า 5,000 บาทของ ว322 สำหรับ อปท. การเลือกนี้ยังเป็นข้อมูลร่าง ไม่ใช่การรับรองฐานอำนาจทางกฎหมาย
- ตั้งค่าแหล่งเอกสาร D05–D11 แยกรายฉบับได้ เปิดสร้างร่าง D07 ก่อน แม่แบบอื่นแสดงว่ารอตรวจต้นฉบับ
- แนบ PDF/DOCX/PNG/JPG ได้ไม่เกิน 20 MB เก็บไบต์ต้นฉบับและ SHA-256 ในฐานข้อมูล ไม่ส่งขึ้นบริการภายนอก
- มีหมวด D10 ข้อมูลสาระสำคัญจาก e-GP และ E01 ข้อมูลสัญญาต้นทาง e-GP ที่แสดงใน e-LAAS รวมถึง V01 ฎีกาจาก e-LAAS
- D07 ใช้แม่แบบ Word ที่ตรวจ SHA-256 ตรงต้นฉบับเท่านั้น แก้ข้อความในตำแหน่งที่ตรวจไว้ คงส่วนอื่น 18 ส่วนใน DOCX และเปลี่ยนสีเตือนแดงเป็นดำ
- แยกข้อมูลกลางจากข้อความเฉพาะ D07 การแก้ข้อมูลกลางไม่ลบข้อความเฉพาะฉบับ
- ในข้อความรายงาน เกณฑ์พิจารณา และข้อเสนอ ใช้ `{{vendor}}`, `{{item}}`, `{{offered}}`, `{{agreed}}`, `{{number}}`, `{{subject}}` เพื่อผูกกับข้อมูลกลางหรือค่าทับเฉพาะฉบับได้ ข้อความที่พิมพ์ชื่อและยอดเองเป็นข้อความอิสระ ไม่แก้แทนผู้ใช้โดยอัตโนมัติ
- ข้อความ “เรียน…” ในส่วนความเห็นผู้อำนวยการกอง/ปลัด ผูกกับตำแหน่งปลัดและผู้มีอำนาจ หรือระบุข้อความเองได้ ทั้ง DrawingML และ fallback
- สร้าง Word ร่าง ดาวน์โหลด และสร้างตัวอย่าง PDF ด้วย Microsoft Word บน Windows ได้ ตรวจว่า PDF มีหนึ่งหน้าก่อนเก็บให้ดูในระบบ
- เก็บไฟล์ที่สร้างเป็นฉบับคงที่พร้อมข้อมูลและเวอร์ชันขณะสร้าง แก้ข้อมูลกลางแล้วแจ้งฉบับเก่าต้องตรวจหรือสร้างใหม่ รวมถึงเมื่อเวอร์ชันแม่แบบเปลี่ยน
- บันทึกประวัติข้อมูลแต่ละเวอร์ชัน ตรวจการแก้ชนกันจากหลายหน้าต่าง และเตือนข้อมูลยังไม่บันทึกเมื่อออกจากหน้า
- เพิ่มข้อมูลจัดซื้อจัดจ้าง ประวัติ แม่แบบส่วนตัว และไฟล์ในระบบสำรอง/กู้คืนเดิมของแอป

## ขอบเขตแม่แบบ D07

เวอร์ชันผลลัพธ์ปัจจุบัน `D07-black-v2` เพิ่มช่องข้อความเรียนในส่วนความเห็นจาก `D07-black-v1` โดยไม่เปลี่ยนตำแหน่งวัตถุหรือรูปแบบย่อหน้า ต้นฉบับอ้างอิงยังคงเดิม:

`3b6d0541a216951bf48f0e51f8c227aa34ab947f8ab6646083bd4fc818a7ef31`

ตัวแม่แบบติดตั้งผ่านการเลือกไฟล์ D07 เดิม ไฟล์ส่วนตัวไม่ฝังใน Git หรือโฟลเดอร์ public แบบฟอร์มงานใหม่เริ่มจากข้อมูลว่าง ไม่ดึงชื่อร้าน/รายชื่อบุคคลจากงานตัวอย่างมาใช้

ร่างนี้รองรับรายการบรรยายหนึ่งรายการและการคำนวณยอดรวมภาษี 7% ตามตารางต้นฉบับ ต้องเพิ่มรูปแบบหลายรายการและภาษีแบบอื่นภายหลัง ข้อความแก้ได้ในย่อหน้าเดิม ยังไม่เพิ่มย่อหน้าหรือวัตถุลงนามอย่างอิสระ

แม่แบบมี footer เก่าที่ซ่อนในหน้าแรก ส่วนใบต่อยังไม่ผ่านการปรับปรุง จึงปฏิเสธตัวอย่าง PDF ที่ล้นเป็นหลายหน้า และระบุให้ตรวจ Word ก่อนพิมพ์ลงนาม ไม่อ้างว่าเอกสารหลายหน้าผ่านการตรวจแล้ว

## สถานะการเปิดใช้งาน

โค้ดอยู่ในระบบหลักแล้ว การทดลองรอบนี้เปิด **Workspace หลักบนฐานข้อมูลแยก** ที่ `http://127.0.0.1:3108/?view=procurement` ไม่ใช่หน้าร่างแยก `/procurement/template` และไม่ย้ายงานทดลองเข้าสู่ฐานข้อมูลงานจริง

เปิดด้วย Node 22: `node scripts/procurement-main-demo.mjs` หรือ `npm run dev:procurement-main` ใช้ `output/procurement-main-demo/main-demo.sqlite` และ marker `SAFETY-TEST-ONLY` ปิดงานสำรองอัตโนมัติและการเชื่อมต่อ Google ของตัวทดลอง

การ build ตรวจสอบรุ่น desktop ไม่เท่ากับสลับรุ่นที่กำลังเปิดอยู่ สถานะติดตั้งจริงต้องบันทึกแยกจากผลทดสอบ ก่อนสลับรุ่นต้องผ่านการตรวจหน้าจอ ไฟล์ และระบบสำรองขั้นนี้ ไม่ต้องรอทำครบทุกแม่แบบเพื่อเชื่อมเมนูหลัก แต่ยังไม่ควรใช้ชุดเอกสารทั้งกระบวนการจนกว่าแต่ละแม่แบบจะผ่านการตรวจ

**ผลติดตั้งขั้นแรก: ติดตั้งและเปิดรุ่นหลักที่พอร์ต 3000 แล้ว** (`http://127.0.0.1:3000/?view=procurement`) หลัง TypeScript, ชุดทดสอบที่เกี่ยวข้อง 33 ข้อ และ production build ผ่าน ติดตั้งเฉพาะแม่แบบ D07 ที่ตรงต้นฉบับให้พร้อมใช้ ไม่ย้ายงานสมมติเข้าฐานข้อมูลจริง

สำรองก่อนติดตั้งเก็บที่ `output/procurement-main-install/สำรองข้อมูล/` และบันทึกรุ่นก่อนหน้าไว้ที่ `output/procurement-main-install/previous-desktop.json` ตรวจข้อมูลและไฟล์เดิม 13 ตารางด้วย SHA-256 เทียบกับฐานข้อมูลสำรอง พบว่าคงเดิม งานจัดซื้อจัดจ้างในฐานจริงเริ่มต้น 0 งาน หลักฐานการติดตั้งและภาพหน้าจอจริงอยู่ที่ `output/procurement-main-install/verified.json` และ `installed-main.png`

## การตรวจสอบ

- `tests/procurement-main.test.ts`: ซื้อ/จ้างแยกงาน การแก้ชน ประวัติ ข้อความเฉพาะฉบับ ไฟล์หลักฐานไม่เปลี่ยน ลายเซ็นไฟล์ เส้นทางอันตราย เงื่อนไขวงเงินแม่แบบ ไฟล์ร่างคงที่ และสำรอง/กู้คืนรวมแม่แบบ/หลักฐาน
- `tests/procurement-template.test.ts`: ตรวจ XML และทุกส่วนที่ต้องคงไว้กับต้นฉบับส่วนตัวจริง
- `scripts/test-procurement-main.mjs`: ใช้ Chrome กับ Workspace หลัก สร้างงานจริงในฐานทดลอง กรอกข้อมูลครั้งเดียว สร้าง Word/PDF แนบไฟล์ แก้ข้อมูล เปิดกลับ ดูประวัติ ตรวจการออกจากหน้าขณะยังไม่บันทึก ปฏิเสธคำขอจากเว็บไซต์อื่น และตรวจหน้าจอ 390 px
- หลักฐานการทดลอง: `output/procurement-main-demo/qa/report.json`, `main-overview.png`, `main-mobile.png`, `main-D07.docx`, `main-D07.pdf`
- ตรวจภาพ PDF จริงพบและแก้ชื่อหน่วยงานเก่าในข้อความเรียนส่วนความเห็นทั้งสองจุด เพิ่มเงื่อนไขทดสอบไม่ให้ข้อความหน่วยงานเดิมค้างในเนื้อหางานใหม่

## ขั้นถัดไป

1. ทดลองใช้งานเมนูหลักขั้นแรกที่ติดตั้งแล้ว โดยตรวจ Word/PDF ก่อนนำเอกสารร่างไปใช้จริง
2. ตรวจแม่แบบ D01 เป็นต้นไปเทียบต้นฉบับ เพิ่มรายการพัสดุหลายรายการและแบบภาษี โดยเลือกชุดเอกสารตามแนวทาง/เงื่อนไขที่ยืนยัน ไม่สร้างเอกสารราชการจากระบบภายนอกขึ้นเอง
3. เพิ่มการเลือกไฟล์หลักสำหรับพิมพ์/ส่งคลัง การนำ Word กลับพร้อมตรวจความต่าง และเวอร์ชันลงนามที่แก้ไม่ได้
4. ทำใบต่อ “ใบต่อบันทึกข้อความ เรื่อง … ที่ … ลงวันที่ …” และจัดกลุ่มลายเซ็นเมื่อข้อความยาว โดยไม่ย่อฟอนต์อัตโนมัติ
5. เพิ่มสัญญา งานย่อยตามลำดับ วันหยุด ประวัติแก้กำหนดเวลา และการแจ้งเตือน แยกกำหนดสัญญาจากเป้าหมายภายใน
6. เชื่อมลงรับคลังรอบแรก รับเอกสารกลับมาดำเนินการต่อ นำเข้าฎีกา e-LAAS และปิดงานเมื่อคลังลงรับรอบสอง สถานะจ่ายเงินจริงเป็นข้อมูลติดตามแยก
7. เชื่อมแฟ้มจัดซื้อจัดจ้างกับการจัดแฟ้มในเครื่องและ Drive แบบรายเรื่อง ปัจจุบันหลักฐานอยู่ในฐานข้อมูลและรวมในชุดสำรองแล้ว

เงื่อนไขระเบียบและส่วนที่ยังรอตรวจต้นฉบับอ้างอิงอยู่ใน `docs/procurement-procedures-20261115.md` ไม่ควรแปลผลการทดสอบโปรแกรมว่าได้ตรวจความถูกต้องทางกฎหมายครบทุกกรณี
