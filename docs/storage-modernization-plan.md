## หลักฐานขั้น 1

โปรเจกต์ที่รัน localhost:3000 ตรวจด้วย instance hash ตรงกับโฟลเดอร์ source จริง ไม่อิง cwd ที่ค้างอยู่จากเครื่องเก่า

รายงานเฉพาะเครื่องอยู่ที่ `output/storage-audit/`:

- `baseline.json`: โฟลเดอร์ฐานข้อมูล ตัวนับไฟล์ และสถานะที่อ่านจากฐานข้อมูลจริง
- `backup-verification.json`: ตำแหน่งสำรองและผลเทียบข้อมูลทุกแถว/ไบนารี 25 ตารางหลังทดลองกู้คืน
- `drive-verification.json`: ผลตรวจ Drive แบบอ่านอย่างเดียวผ่านบัญชีที่แอปเชื่อมอยู่ รวมการตรวจฐานข้อมูลสำรองบน Drive
- `phase-1-report.md`: รายงานอ่านง่าย

มี checkpoint ส่วนตัวใน `output/storage-audit/checkpoint-...` ประกอบด้วย SQLite เต็มชุดและค่าระบบเดิม จำกัดสิทธิ์ Windows เฉพาะผู้ใช้ปัจจุบันและ SYSTEM ห้ามนำ checkpoint นี้ขึ้น Git หรือ Drive เพราะมีข้อมูลเชื่อมต่อ ชุดสำรองข้อมูลธุรกิจแยกอยู่ในโฟลเดอร์สำรองปกติและไม่รวมค่าลับ

ครั้งนี้ยังไม่มีการย้ายฐานข้อมูล เปลี่ยนการจัดเก็บ หรืออัปโหลดข้อมูลใหม่ไป Drive

## ข้อค้นพบที่ต้องแก้

- `storage:local` ปัจจุบันควบคุมสำเนา/ส่งออก ส่วนฐานข้อมูลใช้ `DATABASE_PATH` แยกกัน การตั้งค่าโฟลเดอร์ยังไม่ใช่การย้ายฐานข้อมูล
- ไฟล์แนบเก็บใน SQLite พร้อมสำเนาโฟลเดอร์เอกสารแนบรวม ไฟล์แยกยังไม่มีแฟ้มของเรื่องต้นทาง
- signed_scans เก็บไบนารีและ document_id ใน SQLite แต่ยังไม่มี mirror รายเรื่องหรือ Drive sync เฉพาะฉบับลงนาม
- รูปเอกสารแนบท้ายเก็บใน document_appendix_images และอ้างผ่าน documents.data.appendixImages
- ไฟล์แนบผูกผ่าน documents.data.attachmentFiles ต้องสำรวจร่างกู้คืนและกรณีหนึ่งไฟล์ถูกอ้างโดยหลายร่าง ห้ามลบสิ่งที่ยังไม่พบ owner โดยอัตโนมัติ
- โครงการมี project_id/task_id/stage พร้อมแล้ว แต่ยังไม่มีแฟ้ม Drive รายโครงการ
- พัสดุมี local mirror และส่ง Drive รายไฟล์ได้ แต่ไม่ได้ส่งอัตโนมัติเมื่อแนบ
- สำรองอัตโนมัติทำลง local; การซิงก์/สำรองขึ้น Drive เป็นคนละคำสั่ง
- เอกสาร PDF บน Drive อาจรวมหน้ารูปและไฟล์แนบ แต่ไม่เท่ากับเก็บต้นฉบับรูปหรือฉบับลงนามแยกไว้
- รหัส Drive ที่จองไว้ใน settings ยังไม่ใช่หลักฐานอัปโหลดสำเร็จ ต้องยืนยันจาก API และบันทึกผลสำเร็จจริง
- เส้นปะความเห็นอยู่ใน render-document.ts (.opinion-line / เติมจุด) และแปลง Word ผ่าน word-layout.ts ต้องตรวจร่วมกับเส้น memo-value ไม่แก้ UI CSS อย่างเดียว

## การออกแบบขั้นถัดไป

1. หมวดตั้งค่า: หน้าตา/หน้าหลัก, หน่วยงาน, รายการกรอกอัตโนมัติ, คลังคำศัพท์, Drive, ที่เก็บและสำรอง, ความพร้อมระบบ แบ่งย่อย appearance เป็นทางลัด/พื้นหลัง/นาฬิกา/ส่วนหัวเมนู รักษาสถานะฟอร์มที่ยังไม่บันทึก
2. Browse ต้องเลือกโฟลเดอร์บนเครื่องที่รันโปรแกรมจริง มีแผนย้ายให้ดู ตรวจสิทธิ์ พื้นที่ และไฟล์ปลายทางก่อนเริ่ม โดยไม่ใช้ file input ที่ให้ได้เฉพาะชื่อโฟลเดอร์ฝั่ง browser
3. เก็บตัวชี้ตำแหน่งฐานข้อมูลใน bootstrap config ที่อ่านได้ก่อนเปิด SQLite ตรวจทุก entrypoint: desktop/dev/backup/restore/export/test การย้ายต้องหยุดงานเขียนชั่วคราว สำรอง คัดลอก ตรวจ hash แล้วสลับตำแหน่งและ restart อย่างมีการประสานงาน เก็บชุดเดิมเพื่อย้อนกลับ
4. โฟลเดอร์ฐานรากแยก `ฐานข้อมูล`, `หนังสือราชการ`, `โครงการ`, `พัสดุและครุภัณฑ์`, `คลังกฎหมาย`, `สำรองข้อมูล` แต่ละเรื่องใช้ ID คงที่ร่วมกับชื่ออ่านง่าย ภายในแบ่งร่าง/ฉบับลงนาม/เอกสารแนบ/รูปประกอบ
5. สร้างแผนผังไฟล์อ้าง owner และหมวดย่อย แยกต้นฉบับกับไฟล์แปลง ไม่เปลี่ยนความสัมพันธ์เดิม ไม่ลบไฟล์ร่วมใช้หรือข้อมูลค้างจากร่างที่ยังไม่ได้บันทึก
6. Drive ใช้เจ้าของเรื่องและ stable ID เดียวกัน มีสถานะค้าง/กำลังส่ง/สำเร็จ/ผิดพลาด รายไฟล์ ทำซ้ำแล้วไม่สร้างไฟล์ซ้ำ เคารพเงื่อนไขหนังสือลับเดิม และไม่สร้างสิทธิ์แชร์เพิ่มเติม
7. ทดสอบไฟล์ชื่อซ้ำ เปลี่ยนชื่อเรื่อง ไฟล์ถูกอ้างหลายเรื่อง เปิดหลายหน้าต่าง ย้ายปลายทางที่เขียนไม่ได้ Drive offline/หมดสิทธิ์ สำรองกู้คืน และเปิดระบบหลัง restart

ผลลัพธ์เอกสารราชการต้องคงเดิม ยกเว้นเส้นปะความเห็นที่ผู้ใช้ระบุให้แก้ ไม่ push GitHub จากขั้นตรวจสอบนี้โดยอัตโนมัติ

## ผลขั้น 5 — แฟ้มภาษาไทยและ Drive (6 พฤศจิกายน 2569)

- ย้ายหมวดงานอังกฤษเก่า 13 หมวด (26 โฟลเดอร์รวมปี) เป็นหมวดภาษาไทย ตรวจ hash ไฟล์เดิมครบ 16 ไฟล์ ไม่มีไฟล์สูญหาย ไม่เปลี่ยนชื่อเรื่องที่ผู้ใช้ตั้งเอง
- เพิ่มแผนซิงก์รายเรื่องในตั้งค่า: เตรียมรายการ เริ่ม/ทำต่อ หยุดหลังไฟล์ชุดปัจจุบัน ค้นหา กรองรายการผิดพลาด และลิงก์ไฟล์ที่ส่งสำเร็จ
- Drive จัดหมวด/ปี/เรื่องและหมวดย่อยเหมือนในเครื่อง รวมข้อมูลร่าง ต้นฉบับไฟล์แนบ รูป ฉบับลงนาม และ PDF/Word รุ่นปัจจุบันที่ส่งออกแล้ว ไม่เปลี่ยนสถานะตรวจทานหรือเลขทะเบียน
- จองรหัสก่อนส่งและตรวจ checksum จาก Drive ก่อนแสดงสำเร็จ ทำซ้ำไม่เพิ่มไฟล์เดิมซ้ำ ไม่เขียนทับไฟล์ที่มีผู้แก้บน Drive และไม่ลบรุ่นเก่าอัตโนมัติ
- ทดสอบหน่วย 37 กรณีและเบราว์เซอร์ 21 กรณีผ่าน รวมเครือข่ายขาด การทำต่อ สิทธิ์ปลายทาง เอกสารลับ และ Word ทั้ง 13 แบบฟอร์ม ตรวจ TypeScript และ build ผ่าน
- ซิงก์งานจริงสำเร็จ 128/128 ไฟล์จาก 36 แฟ้ม ข้อมูลธุรกิจ 25 ตารางเทียบก่อน–หลังตรงกัน ไม่พบ client error หรือแนวนอนล้นที่ 375 px
- ตรวจ Drive แบบอ่านอย่างเดียวอีกครั้ง: checksum/ขนาด/เจ้าของ/ลำดับโฟลเดอร์ตรงครบ 128 ไฟล์ ไม่มีรหัสไฟล์ซ้ำ ดาวน์โหลดตัวอย่าง 9 ไฟล์เทียบ SHA-256 ตรงทั้งหมด
